Crypto Officer 인쇄 책자

자기 책자의 현재 단계만 펼칩니다. 진행자가 “단계.번호, 업무”를 부르면 해당 행을 찾습니다. 먼저 수행하지 않습니다.

공용 기록지의 같은 번호·본인 이름 칸에 직접 기록합니다. 끝나면 “S01.2, Key Custodian 2, 완료”처럼 번호·담당·결과를 말합니다. 이상은 즉시 중단 요청합니다.

입회자는 단계 전체를 관찰합니다. 대기 표시는 역할 해제나 퇴장을 뜻하지 않습니다. 단계 종료와 다음 단계 이동은 Administrator가 선언합니다.

종이 확인 서명은 생성 계획·HSM 토큰의 전자서명을 대신하지 않습니다. 개인 승인키는 승인된 장치에서 본인이 사용합니다.

Crypto Officer / Key Custodian 1 담당자 가이드

초안 · 승인된 명부에서 배정된 담당자만 수행합니다.

생성·서명을 실행하고 Key Custodian 1을 겸합니다. 단독 실행·승인 검사 우회·승인 후 입력 변경·자기 결과의 독립 검증·결과 불명 상태의 재실행은 금지합니다.

시작 전에 본인 역할 임명·교육, 승인된 문서 버전·계정과 필요한 도구를 확인합니다. 모르는 값이나 불일치는 추측해 채우지 말고 중단을 요청합니다. 정책값은 설정표 — 별책「승인 설정」, 실제 명령은 실행 절차 — 별책「실행 절차」, 역할 분리는 공통 규칙 — 책자 앞면의 역할 규칙을 따릅니다.

겸임 승인 규칙

생성 때는 전체 명단·대상·설정·작업 ID·기한이 연결된 생성 계획을 개인 승인키로 서명합니다. 인증서/CSR 서명 때는 고정 본문을 먼저 승인하고 같은 작업·키·기한·세션에 연결된 새 HSM key-usage 토큰을 개인 승인키로 서명합니다. 등록 토큰·생성 계획·key-usage 토큰의 서명을 서로 대체하거나 재사용하지 않습니다. CA 개인키는 CloudHSM 밖으로 꺼내지 않습니다. 자기 승인은 다른 보유자 1명 이상의 승인과 함께만 유효하며 어느 두 보유자의 조합도 허용합니다.

시작 확인 — 자기 역할의 세부 기준

S00.2에서 자료 2의 본인 인적 사항·실행/Key Custodian 1 겸임과 개인 CU·등록 공개키를 대조합니다. 책자 ID도 확인합니다. 다른 보유자의 개인키를 제시받거나 보관하지 않습니다.

S00.3에서 자료 3의 실제 환경 조회 결과·시각, 자료 4의 초기 설정 인수·승인 통제/우회 시험 근거, 자료 5의 로그 수집·저장소 쓰기/조회 시험 결과를 제시합니다. 승인값과 실제값이 나란히 있는 표와 해당 원문을 함께 펼칩니다. 과거 시험과 현재 조회를 구분하고 미실시·불일치를 숨기지 않습니다. 자료 5의 보호 인수/보관 계획은 Administrator가 제시합니다.

제시 후 “S00.3, Crypto Officer, 자료 3·4·5의 시험 근거 제시 완료” 또는 “S00.3, Crypto Officer, 자료 [번호] 누락으로 보류 요청”처럼 보고합니다. S00.4 검토 중 질문을 받으면 근거를 보여 주고, 설정 변경·키 생성·CA 서명은 하지 않습니다. S01로 이동하라는 선언 이후에도 S01의 작업별 승인이 있어야 생성합니다.

Root 키 생성 · 열 기록지 — 기록지 S01

  • 준비: Root 작업 ID와 생성 계획·내용표·해시를 제시합니다. 계획에는 승인자 전체 명단·CU/공개키·소유/공유·생성 파라미터·quorum을 연결합니다.

S00-R 제한 재개 절차

  1. Administrator는 이전 서명 목록·대기 사유·custody·임시 접근 종료 기록과 미완료 항목을 대조합니다. 새 키 생성이나 HSM 서명을 포함하지 않는 재개인지 확인합니다.
  2. Administrator는 필요한 환경·권한·데이터의 동일성, 대기 중 변경과 사고 여부, 백업·로그 수집·기록 저장 상태를 확인합니다. 역할별 유효 자격과 승인된 관찰 범위를 확인하고, 실제 조회에 Crypto Officer나 다른 담당자가 필요하면 그 사람의 참여·최소 접근을 기록합니다. Key Custodian 2·Key Custodian 3·Independent Witness의 재참석 필요 여부는 재개 작업과 승인된 입회 조건으로 판단합니다.
  3. Administrator는 “이전 생성·서명 기록을 유지하고 S06의 남은 백업·증거 검사와 S07 종료만 재개합니다”라고 승인합니다. S00의 Root 생성 시작 선언이나 S01–S05를 반복하지 않습니다. 범위가 달라지면 제한 재개를 취소하고 별도 변경 승인을 받습니다.
  4. Administrator는 회차·참석·조회 접근·검사 범위·재개 승인을 E00-RESUME에 기록합니다. 후속 수행자들은 추가 기록에 자신의 범위만 확인 서명합니다.

중단과 재개

  1. 발견자는 단계와 사유를 알리고 Crypto Officer는 후속 생성·서명 요청을 중단합니다. Administrator는 시각·마지막 명령·현재 결과를 기록합니다.
  2. Administrator·Crypto Officer는 생성 키 조회와 서명 결과 복구를 구분합니다. 서명은 원장 상태표 — 별책「실행 절차」와 내구 저장된 실행기 요청·응답을 확인합니다. HSM/CloudWatch 관리 로그만으로 해당 본문의 서명 성공·미실행 또는 서명값 복구를 단정하지 않습니다. 상태 확인 전 재실행·삭제하지 않습니다.

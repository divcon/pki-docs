# 종이로 진행하는 세레모니 — 인쇄 묶음

**2026-10-12 작성 순서 변경:** 인쇄 묶음은 문서 내용 확정 후 마지막 단계에 작성한다. 현재 HTML·manifest는 이전 검토 초안이며 이후 원문 수정과 동기화하지 않는다. 최종 배부본으로 사용하지 않는다. 모든 기록칸의 `이름/확인 서명`은 손서명 대상을 확정한 정책이 아니며, 항목별 구분을 정한 뒤 최종 서식에 반영한다.

초안 · 미승인. [인쇄·배부 목록](index.html)을 로컬 브라우저로 열어 필요한 책자를 인쇄한다. 모든 HTML은 본문·CSS를 자체 포함하며 외부 폰트·스크립트·네트워크 연결이 필요 없다. 생성·서명·검증은 기존 승인 실행 환경에서 수행하고, 종이 가이드와 기록은 참가자마다 노트북을 갖는 것을 전제로 하지 않는다.

## 읽고 기록하는 순서

1. 진행자가 “전원 S01을 펴세요. 지금 S01.2, 생성 계획 승인입니다”라고 알린다.
2. 각자 자기 책자의 S01 첫 면에서 S01.2를 찾는다. 수행자는 적힌 행동을 하고, 나머지는 대기 또는 계속 관찰한다. 필요한 세부 기준은 바로 다음 면에 있다.
3. 공용 기록지 S01에서 S01.2의 본인 칸에 결과·근거·시각·확인 서명을 남긴다. 앱/HSM 전자서명은 승인 장치로 별도 수행하고 증거 번호를 연결한다.
4. “S01.2, Key Custodian 2, 완료”처럼 보고한다. Administrator가 필수 승인·확인 결과를 대조하고 다음 번호를 부른다. 단계 통과 후에만 다음 단계로 넘긴다.

각 면의 단계·담당자·호출 번호가 위치 표식이다. 종이 묶음에 단계별 탭을 붙이고 페이지가 늘어나도 이 표식으로 찾는다. 사건이 생기면 어느 번호에서 중단했는지 남기고 보류·재개 전용 기록을 사용한다.

## 인쇄 준비

- A4, 배율 100%, 브라우저 머리글/바닥글 끄기를 기준으로 미리보기한다. 내용이 길면 자연스럽게 다음 장으로 이어지며 글자를 잘라 숨기지 않는다.
- 개인 책자는 각 단계의 「지금 할 일」과 「세부 확인」을 순서대로 묶는다. 공용 기록은 단계별로 분리한다. 인쇄 묶음 ID가 같은지 대조한다.
- 별책의 실제 설정·명령·시험 근거와 당일 생성 계획·본문 내용표는 승인된 자료로 채워 제시한다. 현재 문서의 빈칸과 미구현을 완료로 간주하지 않는다.
- 링크/번호/HTML 구조 검사는 실제 인쇄 확인을 대신하지 않는다. 사용 환경의 한글 글꼴·줄 넘침·필기 공간·기록지 전달 동선을 인쇄 리허설에서 확인한다.

## 수정과 재생성

**현재 재생성 보류:** 기록·지시 분리 후 기록지의 대응표는 `RECORD CALLS` 구역으로 관리하고 통과/중단 기준은 담당자 가이드로 옮겼다. 아래 기존 생성기는 이전 문서 구조를 전제로 하므로 최종 인쇄 작업 재개 시 먼저 동기화 범위·판정 기준의 원천·서명란을 새 구조에 맞게 수정해야 한다. 그 전에는 아래 명령으로 원문이나 HTML을 갱신하지 않는다.

호출 순서·담당·행동·기록 내용은 `sequence.json`, S00 자료 5종은 `s00-materials.json`, 상세 기준은 상위 `guides/`·`records/`·설정/실행 문서에서 수정한다. `build.py`는 호출표와 개인 가이드의 자료 5종 표를 Markdown에 동기화하고 모든 인쇄 HTML과 원문 해시 목록을 다시 만든다. 생성된 HTML을 직접 수정하지 않는다.

```sh
python3 root-key-design/ceremony/root-first-001/print/build.py
python3 root-key-design/ceremony/root-first-001/print/check.py
```

Python의 `markdown-it-py`를 사용한다. 생성 과정은 외부 접속이나 행사 실행을 하지 않는다. `manifest.json`의 build ID와 원문 SHA-256은 생성본 식별용이며 행사 승인 서명이 아니다. 변경 후에는 전체 묶음을 재생성·검토하고 같은 ID의 출력물로 교체한다.

2026-10-12 S00의 호출·역할·자료·기록·진행 조건을 문서상 점검했다. [점검 결과와 남은 확인](../preparation.md#s00-인쇄-문서-점검--2026-10-12)을 참고한다. S00 기록지는 호출/작성자마다 새 면에서 시작한다. 실제 출력·필기·현장 리허설은 아직 수행하지 않았다.

## 진행 순서

S00에는 자료 5종과 가이드 검토 항목 20개가 연결되어 있다. 그 구조를 짧게 확인한 뒤 **S01 Root 키 생성**을 첫 상세 점검 대상으로 한다. 각 단계의 정상·예외 흐름과 자료/기록 대응을 완료한 뒤 S02–S07을 순서대로 진행한다. 문서상 점검과 실제 리허설은 구분한다.

S01의 현재 흐름은 다음과 같다. 이것은 검토 시작점이며 실제 문서를 확인한다.

1. S01.1 Crypto Officer가 Root 생성 계획·작업 ID·해시·설정·승인 명단 제시.
2. S01.2 세 Key Custodian 중 서로 다른 2명 이상이 같은 계획을 개인 승인키로 승인. 승인/거부/미참여 구분.
3. S01.3 Administrator가 승인·앱 검증·명단/등록키 연결 및 활성화된 실행 접근의 범위·입회 상태 확인. 접근 통제 담당의 실제 행위도 구분.
4. S01.4 Crypto Officer가 승인된 요청만 실행하고 결과 제시.
5. S01.5 Administrator가 키 식별·공개키·속성·소유/공유·quorum·노드 상태를 독립 검증하고 보호·백업 추적.
6. S01.6 생성 접근 회수와 잔여 접근 확인. 후속 서명에 필요한 지속 계정·소유/공유를 임의 삭제하지 않음.
7. S01.7 Witness가 실제 관찰 범위를 기록하고 Administrator가 결과·보호·회수·증거를 확인해 진행/보류/중단 판정.

## 호출별 점검 기준

각 호출을 아래 항목으로 검토한다. 부족하면 script·해당 개인 가이드·records를 함께 고친다.

| 항목 | 확인할 질문 |
|---|---|
| 진입 조건 | 무엇이 확인된 뒤 이 호출을 시작하는가? 미완료면 누가 멈추는가? |
| 역할 | 실행·검증·승인·입회·대기 담당이 분명한가? 겸임을 여러 사람으로 세지 않는가? |
| 입력 자료 | 누구에게서 어떤 ID/버전의 자료·원문을 받으며 승인본과 무엇을 대조하는가? |
| 순서 | 승인 전 실행·판정 전 이동·실제 선언 전 입회 서명 같은 시간 역전이 없는가? |
| 다자 통제 | 같은 대상에 유효한 서로 다른 2명의 승인이 연결되는가? 생성 앱과 HSM 토큰 승인을 혼동하지 않는가? |
| 실행·검증 | 실행 가능 선언의 조건과 독립 결과 검증을 구분하는가? |
| 기록 | 누가 공용 records의 어느 칸에 결과·근거·시각을 남기는가? 개인 메모와 이중 작성은 없는가? |
| 종료 | 완료 보고를 누구에게 하고 누가 다음 호출을 선언하는가? |
| 예외 | 거부·자료 누락·입회 단절·불일치·결과 불명·저장/백업 실패에서 정지·보호·재개 범위가 분명한가? |

## 문서별 수정 원칙

- script는 해당 담당자를 호출하고 가이드에 따라 확인·수행한 뒤 records 어디에 기록할지 안내한다. 검토 표 전체나 미정 개발 상세를 복사해 장황하게 만들지 않는다.
- 개인 가이드는 본인의 자료·대조 기준·행동·완료 보고·보류 조건을 설명한다. 다른 역할의 가이드를 찾아다녀야만 본인 일을 이해하는 구조를 피한다.
- records에는 실제 결과·판정·근거·작성자·시각·서명 및 작성 안내만 둔다. ‘Administrator는 먼저 무엇을 실행한다’ 같은 절차를 다시 넣지 않는다. 필수 판정의 결과란 자체는 없애지 않는다.
- 자료별 검토 기준은 가이드에 둔다. A의 자료 ID/항목과 대응시키고 아직 없는 링크를 완료된 연결처럼 만들지 않는다.
- 기존 `S01.1` 같은 호출 번호는 가급적 유지한다. 변경이 필요하면 script·다섯 가이드·records의 대응을 함께 수정하고 A에게 전후 표를 전달한다. print/sequence.json은 현재 기준으로 취급하지 않는다.
- 일반 기록·책임 확인·암호학적 전자 승인을 구분한다. 손서명 정책은 제안 상태이므로 모든 칸에 새 손서명 의무를 만들거나 기존 필수 확인 서명을 근거 없이 삭제하지 않는다. 항목별 권고안과 사용자 선택 필요 사항은 진행 파일에 분리한다.
- 가이드에 기록 준비·보관 지시를 추가할 수 있으나 설계 미정/보류 목록은 진행 파일을 통해 preparation 통합 요청으로 보낸다.

## 예외에서 유지할 통제

승인 0/1명·동일인 중복·승인 대상 변경·등록키/명단 불일치·미승인 권한 경로를 통과시키지 않는다. Witness의 관찰 누락을 뒤늦은 서명으로 덮지 않는다. 생성 결과 불명·부분 복제·서명 응답 유실과 원본 응답 저장 성공을 구분한다. 결과 불명 상태의 자동 재실행·삭제, 백업 READY만으로 신규 키 포함 완료 판정은 금지한다. 동일 저장 응답은 조립/검사만 복구하며, S00-R의 제한 범위를 유지한다.

관리 quorum·속성 잠금·폐기 경로·N01/N03·상태 서비스 준비의 미해결 조건을 단순한 문구 정리로 해제하지 않는다. S00에서 운영 키가 아직 없는 것과 필수 사전 시험이 미실시인 것을 구분한다.

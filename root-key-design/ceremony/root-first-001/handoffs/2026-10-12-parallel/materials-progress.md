## 2026-10-12 — S00 작성 시점·기입 안내 정리

사용자가 수정 금지를 해제하고 S00의 핵심 기입 가이드·세 시점 구분·기존 결정값 반영을 직접 요청했다. 이번 범위에 한해 materials 외에 `guides/README.md`, 역할별 가이드 5종의 S00, `records/s00-start.md`를 함께 수정했다. B의 진행 파일·script 및 동시에 작성 중인 가이드 S01 변경은 덮어쓰지 않았다.

## 2026-10-12 S00-v2 — 역할별 가이드 간결화

사용자의 가독성 재검토 요청에 따라 가이드 5종 S00을 다시 정리했다. 기존 호출표·세부 설명·전체 자료 목록에서 반복하던 내용을 제거하고 본인 준비 문서/작성 범위, 직전 갱신, 호출별 기입 위치를 남겼다. 사전 수행 승인권자 미정과 Administrator의 S00.4 검토·S00.5 시작 판정을 각 가이드 첫머리에 구분했다. Key Custodian 2·3과 Witness는 전체 자료 양식을 작성하지 않고 본인 근거를 Administrator에게 제공하며, 직전 별도 작성이 없음을 표시했다.

Administrator의 검토 항목 20개와 기준은 그대로 보존했다. 다른 역할에는 본인 확인 범위와 보류·변경·입회 조건을 남겼다. S01 이후와 print는 수정하지 않았다. B의 새 S01 자료 요청 B-001–005는 확인했으며 이번 S00 가독성 수정의 범위에는 포함하지 않았다.

검증: 관련 14개 파일의 로컬 링크 143개(앵커 75개)·표/공백 검사 통과. Administrator 검토 표 20행이 이전과 동일하고, 역할별 S00.1–.5와 세 작성 시점·판정 담당 표시를 확인했다. S00 본문은 Administrator 6,588→4,525자, Crypto Officer 3,426→1,751자, Key Custodian 2/3 각각 2,896→1,371자, Witness 2,973→1,261자로 줄었다. 문서 검사 결과이며 실제 현장 사용성·리허설을 검증한 것은 아니다.

## 2026-10-12 — 역할 배정 후 준비 안내

사용자의 모든 가이드 적용 요청에 따라 역할별 가이드 5종의 도입부와 공통 README를 수정했다. 처음 할 일, 준비 순서, 직접 수행할 일과 받을 자료·요청처, 완료 근거·현재 상태, 당일 단계별 역할, 제출·보고·승인 담당을 표시했다. 공통 용어와 작업 번호 풀이도 연결했다.

Crypto Officer의 환경/절차 인수·시험 보고서 취합과 별도 배정된 시험 수행을 구분했다. Administrator는 담당·기한 조율, 독립 검증·인수 준비와 사전 수행 승인 확보를 맡는다. Key Custodian 2·3은 본인 계정·승인키·승인 연습·본인 근거를, Witness는 독립성·관찰 접근·기록 연습을 준비한다. 지원 담당·행사 일정·사전 승인권자 미정과 실제 구현·시험 미완료를 유지하며 새 담당·권한·완료 상태를 임의 확정하지 않았다.

## 2026-10-12 — script 연결 점검

사용자가 script와 현재 문서의 연결 상태를 질문해 대조했다. script·guides·records·materials의 로컬 링크 275개에 깨진 대상/앵커가 없으며 S00–S07 호출 번호 52개는 script·각 개인 가이드·단계별 records에 모두 존재한다. 이는 실제 기입 위치·행동 순서의 정합성 완료를 뜻하지 않는다.

- 단계별 script에서 해당 기록지 파일이나 역할별 해당 단계로 직접 연결하지 않고 ‘기록지 Sxx / 본인 칸’으로 안내한다. 회차 목록 경유는 가능하나 실제 란 이름까지 안내하지 않는다.
- S06.3의 가이드 기록 위치는 역할 이름으로 안내하지만 실제 서명란은 records/s06-verification.md의 ‘수행 확인 서명’ 표다. Witness의 ‘단계 마감의 입회란’도 실제 제목 ‘Independent Witness’와 다르다. 같은 호출 번호가 존재하는 것과 작성 위치가 명확한 것을 구분해야 한다.
- S00.5/S01.7은 이견 보고 → Administrator 선언 → Witness의 실제 선언 기록 완료 → 다음 이동을 명시한다. S02.8/S04.8/S05.8은 Administrator가 입회 기록을 확인·선언하는 문장이 Witness 기록보다 먼저 나오고 완료 보고 순서는 없다. S03.7도 선언 후 기록 완료 순서가 없다. 단계별 마감 절차의 선후 관계를 대조해야 한다.
- materials는 S00만 존재한다. S01.1의 생성 계획 등 후속 단계의 요구 자료를 가이드 설명에서 찾을 수는 있으나 실제 제시 양식·항목 ID로 연결되지 않는다. S01 양식 작성과 B-001–005 대응은 A의 미완료 작업이다.

앞선 A-003은 신규 역할 안내를 추가한 작업이며 script 전체와의 통합 검토까지 완료한 작업이 아니다. 이번에는 연결 상태를 점검하고 요청만 기록했다.

## 2026-10-12 S00-v3 — 상세 절차·낭독 지시 통합

사용자는 C2PA 제출용 script 구성과 S00의 명확한 진행 지시 작성을 요청한 뒤, 별도 낭독 대본보다 한 script에 절차와 대사를 함께 두는 방식을 제시했다. 이전 별도 대본 제안을 정정하고 script 공통부와 S00을 한 문서로 정리했다. 최신 사용자 요청에 따라 기존 A/B 편집 분담을 넘어 해당 부분과 관련 기록 연결을 직접 수정했다.

- 원문: 설계 산출물을 규격 근거에서 제외하고 공식 CP/Conformance Program v0.2를 확인했다. CP의 script 필수 8개 항목과 독립 입회·서명된 script 요구를 본문에 연결했다. 이 파일 구성은 프로젝트 선택이며 유일한 C2PA 지정 형식이라고 주장하지 않는다.
- script: 본문·가이드·settings/runbook·자료·기록의 승인 묶음과 수행 확인 서명 대상을 정의했다. S00.1–.5는 실제 순서대로 읽는 지시, 수행자, 구체 기록란, 완료 보고, 진행/보류 조건으로 작성했다. 자료 2 제시 후 본인 확인, 자료 3–5 제시와 통과 판정 구분, Witness 이견 → 실제 선언 → 기록 완료 → 이동을 명시했다.
- S00 기록: 적용 script·부속 문서 승인 목록 참조, 절차 준수 여부·미수행/일탈을 추가했다. 기록은 records에 한 번 남기며 S00에서 미래 키 생성의 준수 확인 서명을 받지 않는다. 새로운 일률적 손서명 정책은 추가하지 않았다.
- 자료·가이드: M01의 본문/부속 문서 고정 목록, M04-04의 Cloud-Based HSM 조건부 적용 판단, Administrator/Witness의 S00 기록 지시와 공통 문서 역할 안내를 맞췄다. 실제 구성·승인·시험 완료를 임의 확정하지 않았다.
- 범위: 별도 낭독 파일과 인쇄물을 만들지 않았다. script·가이드의 S01 이후 본문과 후속 기록 양식은 이번 변경 대상이 아니다. S01 자료 작성, S06/보류 확인 서명과 고정 script 묶음의 상세 연결, 후속 단계 낭독 지시 정리는 남아 있다.

검증: 관련 10개 파일의 로컬 링크 197개(앵커 116개)·표 구조·공백 검사 및 `git diff --check` 통과. S00.1–.5 순서·역할별 호출·검토 ID 20개 유지, 변경 전 사본 대비 script와 수정 가이드의 S01 이후 본문 동일 확인. 실제 행사·리허설·서명·C2PA 수용 검증은 수행하지 않았다.

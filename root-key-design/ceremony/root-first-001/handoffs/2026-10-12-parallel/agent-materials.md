## 진행 순서

먼저 S00 양식이 표만 있고 필수 자료·원문이 빠지지 않았는지 확인한다. 새 구조를 다시 설계하거나 완료 상태를 부풀리지 않는다. 다음은 **S01 Root 키 생성**부터 작성·검토하고 S02–S07을 단계별로 이어간다. 각 단계마다 B가 사용할 수 있는 묶음을 전달한다.

| 단계 | 우선 파악할 제시 자료의 범위 — 확정된 파일 개수를 뜻하지 않음 |
|---|---|
| S01 Root 키 생성 | 생성 계획·승인 대상, 승인/실행 입력 연결, 결과 내용표·키 조회 원문 참조, 보호·접근 회수·백업 추적 자료 |
| S02 Root 자기서명 인증서 | 고정 TBS 내용표·프로파일/serial 근거, 본문과 토큰 승인 연결, 결과 인증서·독립 검사 원문 참조 |
| S03 First 키 생성 | S01 구조의 First 대상 적용·Root와 별도 키 식별·보호 자료 |
| S04 First CSR | 고정 CRI 내용표·요청 권한·허용 확장·First 키 연결, 승인/서명 및 검증 자료 |
| S05 First 인증서 | 검증된 CSR·발급용 TBS·Root 서명 키·serial·AIA/상태 준비·프로파일 및 결과 자료 |
| S06 전체 검증 | 산출물/키/원장 대응·백업 포함·일탈 처리·고정 서명 대상 목록 |
| S07 인계·종료 | 인수 범위·접근 종료/유지 계정·상태 서비스 운영·후속 증거와 최종 보관 자료 |

자료가 생성 후에만 존재하면 **양식은 사전 준비, 실제 값/원문은 해당 호출 후 작성·제시**로 표시한다. 모든 자료를 행사 전에 실제 값까지 채우라고 요구하지 않는다. 기존 원문·승인 기록·시험 보고서는 참조를 재사용하고 중복 양식을 불필요하게 늘리지 않는다.

## 양식에 필요한 내용

- 단계·자료 ID·자료명, 행사/회차·버전·작성자·작성/갱신 시각.
- 준비·제시 담당, 사전 준비 또는 당일 생성/갱신 시점, 대응 호출 번호.
- 준비자가 실제로 채울 필수 항목과 표. 승인값/정책과 실제 조회·시험·실행 결과를 구분.
- 첨부해야 할 원문 종류와 식별·버전·해시·위치·시각. ‘증거 제출’이라는 한 줄로 끝내지 않음.
- 미비점·불일치·미실시·비적용의 사유·담당·기한·해소 근거.
- 가이드의 검토 기준 및 records 결과란에 연결할 항목 ID. 링크가 아직 없으면 진행 파일에 연결 요청을 남기고 ‘연결 완료’라고 쓰지 않음.

자료 ID는 `S01-M01`처럼 단계가 드러나게 한다. 본문 항목은 기존 S00의 M01-01 방식을 적용할 수 있으나 다른 단계에서 참조할 때는 단계/파일까지 함께 식별한다. 파일명·ID를 전달한 뒤 변경하면 이전/새 대응을 진행 파일에 남긴다.

**materials에 행사 진행 지시·최종 통과 판정을 넣지 않는다.** 사전 시험 보고서의 실제 결과는 자료지만, 행사 검토자의 당일 판정은 records다. 검토 기준 제안은 자신의 진행 파일에 적어 B가 가이드에 반영하도록 한다. 기준을 삭제하라는 의미가 아니다.

## 스스로 검토할 질문

1. 자료 준비자가 이 양식만 보고 무엇을 어떤 원문과 함께 내야 하는지 알 수 있는가?
2. 파일·키·계정·본문·작업·회차가 뒤섞이지 않게 식별되는가?
3. 승인본과 실제값, 사전 시험과 운영 결과를 대조할 수 있는가?
4. 신규 키 생성 전 확보 불가능한 값을 사전 완료 조건으로 잘못 요구하지 않는가?
5. 미정 관리 정책·개발 명령·수치·실명·시험 결과를 임의로 확정하지 않았는가?
6. 각 항목을 누가 무엇과 대조하며 불충족이면 어떤 결과가 되는지 B에게 전달할 수 있는가?
7. 실제 결과/서명 기록을 materials와 records에 불필요하게 두 번 쓰게 만들지 않았는가?

## B에게 전달할 형식

[materials-progress.md](materials-progress.md)에 단계별로 아래 내용을 남긴다.

- 상태: 작성 중 / B 반영 가능 / B 요청 보완 중 / 연결 대조 완료.
- 자료 ID·경로·전달 버전/일자·작성 시점·제시 담당·대응 호출.
- `자료 항목 ID → 대조할 대상·원문 → 충족/보류 기준 제안 → 검토 역할 → records의 필요한 결과 항목` 표.
- B가 가이드/records에 반영해야 할 내용 및 공통 문서 통합 요청.
- 미정 정책·사용자 결정 필요 사항·개발 후속 사항을 분리.
- 수행한 문서 검사와 아직 하지 않은 실제 시험.

단계별 양식을 만드는 것만으로 전체 세레모니 준비 완료를 선언하지 않는다. 최종 보고에는 생성/수정한 자료, 검토 결과, B에게 넘긴 미반영 항목을 명확히 쓴다.

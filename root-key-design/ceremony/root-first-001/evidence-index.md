# Root와 First ICA 세레모니 — 증거 목록

작성 중 · 실제 수집된 증거는 아직 등록하지 않았습니다. 원문 파일을 어디에 보관하고 어떤 작업·승인·검사·서명에 연결하는지 관리합니다. 메인 절차는 [script.md](script.md), 수행·판정은 [records/record-template.md](records/record-template.md)에 대응합니다.

실제 로그·서명·검사 파일은 승인된 접근 통제 저장소에 두고 이 목록에서 위치·버전·해시를 연결할 수 있습니다. 비밀번호·CA 개인키·개인 승인키·복구 비밀·HSM 백업 원본은 문서 저장소나 제출 묶음에 넣지 않습니다. 이 폴더의 양식은 Git으로 관리하되 실제 자료의 반입 범위는 승인된 보관 정책을 따릅니다.

## 단계별 수집 범위

| ID | 연결 단계 | 등록할 원문 증거 |
|---|---|---|
| E00 | S00 | 배정된 네 신뢰 역할의 성명·소속·직책, 역할 임명·허용/금지 행위 숙지·직무 분리·입회 독립성 확인, 승인본·환경·B00 인수·로그/저장 시험·시작 승인 |
| E01 | S01 | Root 생성 접근·요청/응답·키 식별/속성·공개키·회수·보호 인계 |
| E02 | S02 | Root TBS·본문/토큰 승인·세션·원본 응답·인증서·독립 검사·원장 |
| E03 | S03 | First 생성 접근·요청/응답·키 식별/속성·공개키·회수·보호 인계 |
| E04 | S04 | First CRI·승인·토큰/세션·원본 응답·CSR·요청 허가·검사 |
| E05 | S05 | First TBS·승인·Root 서명응답·인증서/체인·검사·원장 |
| E06 | S06 | 전체 대조·신규 키/최종 데이터 백업·로그 수집·일탈·서명 |
| E07 | S07 | 인수·임시 접근 종료·후속 서명·최종 목록·보관확인·최종 판정 |
| E06a-HOLD | 보류·임시 종료 시 | 당시 수행/입회 서명·보호 인수·임시 접근 종료·별도 목록/서명 |
| E00-RESUME | S00-R 적용 시 | 이전 상태·참석·변경·접근·미완료 항목·재개 승인 |

보류/재개가 없으면 해당 행에 비적용 사유를 남깁니다. 여러 회차의 E06/E07은 회차를 붙여 서로 다른 증거로 식별합니다.

E00은 [S00 시작 확인표](records/s00-start.md#시작-자료-5종)의 다섯 자료와 실제 확인 결과·입회 기록·시작 판정에 연결합니다. 자료별 원문 파일은 아래 파일별 목록에 등록하며 요약표의 통과 표시만으로 원문 증거를 대신하지 않습니다.

제시 자료 양식은 [materials/s00](materials/s00/README.md)에 있습니다. S00-M01–05의 실제 작성본과 개별 첨부를 E00에 연결하고 자료 ID·버전·검토 항목 ID(M01-01 등)를 유지합니다. 양식 자체·미작성 첨부란은 수집된 증거가 아닙니다. 사전 시험 보고서의 결과와 당일 S00 검토 판정은 각각 자료 원문과 records에 구분해 연결합니다.

E02/E04/E05에는 [서명 quorum 결정](settings.md#서명-quorum-결정)에 따른 사용 quorum 값 `2`, 승인 가능한 Key Custodians의 신원·CU 계정·등록키 지문, 실제 승인자·조합·개인별 토큰 서명·검사 결과를 연결합니다. 실행자의 자기승인을 사용했다면 Crypto Officer의 토큰 승인 서명과 실행 지시를 각각 기록합니다.

E01/E03에는 생성 계획, 개인 승인키의 2명 이상 승인 서명, 앱 검증 결과, Key Custodians 전체 신원·CU·공개키 지문 연결, CU 등록 확인 및 승인한 계획과 실제 생성 결과의 대조를 연결합니다. 등록 토큰과 생성 계획의 승인 기록을 구분합니다.

E01/E03에는 [개인키 보호 정책](settings.md#개인키-용도와-추출-검토)과 [관리 기본안](settings.md#키-관리와-관리자-통제)의 생성 직후 실제 조회 결과를 연결합니다. 서명 전용·추출 금지·보호 속성, `modifiable=false`·`destroyable=false`, 사용/관리 quorum 각각 `2`, Key Custodians의 소유/공유·등록키를 대조합니다. 일반 반출·금지 연산·속성 변경·소유자 삭제 거부 시험은 리허설 증거에 연결하고 운영 키에 파괴 시험을 추가하지 않습니다.

E00에는 모든 HSM의 관리자 user·quorum·cluster 최종값 `2`, 관리자 개인 계정 3명·등록키, 초기 설정 보호·단독 변경 거부 증거와 별도 통제 인수 자료를 연결합니다. [M01–M08 검토 기록](key-management-control-review.md#다시-검토할-항목과-판정-기록)의 폐기 계획·공유 클러스터 영향·잠금 시험 판정도 시작 조건으로 연결합니다. 초안에 값을 반영한 사실을 설정 완료 증거로 쓰지 않습니다.

관리 또는 관리자 변경을 실제 수행하면 해당 단계의 증거 ID에 작업 ID를 붙여 계획·현재값/변경값·명령·서비스별 토큰·실제 승인자/조합·요청/응답·전후 조회·일탈을 연결합니다. 공유 변경은 승인자 명단 변화와 함께 기록합니다. 별도 통제 작업은 승인 검사·제한된 실행·직접 우회 차단 근거를 남기며 네이티브 quorum 증거로 표시하지 않습니다.

E06에는 신규 키와 최종 사용자·등록키·소유/공유·두 키 quorum·잠금·관리자 서비스 설정의 백업 포함 근거를 연결합니다. 복원 시험은 동일 공개키·현재 승인자·등록키·quorum·잠금·접속 정책 대조와 사용 허가까지 기록합니다. 과거 계정·승인키 복원을 검사한 증거와 실제 운영 백업 확인을 구분합니다.

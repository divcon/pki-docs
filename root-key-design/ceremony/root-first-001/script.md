# Root와 First ICA 세레모니 — 키 생성 절차서와 진행 대본

초안 · 행사 관리명 `root-first-001` · 행사 수행 승인 전

[수행 단계 전체 목차](script-outline.md)

이 문서는 C2PA 검토에 사용할 상세 키 생성 절차서의 본문이며, Administrator가 같은 순서로 읽고 진행하는 대본입니다. 역할별 상세 기준·실행 방법·제시 자료·실제 기록은 아래 승인 부속 문서에 연결합니다. `{{항목}}`은 승인본에 채울 값, `{{현장_항목}}`은 수행 중 기록할 값입니다.

**작성 범위:** 현재는 공통 문서 구성과 S00을 이 형식으로 정리했습니다. S01–S07은 기존 초안이며 상세 절차·자료·서명 연결의 후속 정리가 필요합니다. 실제 준비·시험·행사 승인·수행은 미완료입니다.

Administrator는 본문과 적용 부속 문서의 파일·버전·해시를 [S00-M01의 승인본 목록](materials/s00/01-event-approval.md#m01-03-승인본배포본-목록)으로 고정하고, 행사 수행 승인 원문에 그 목록을 연결합니다. 본문만 승인하고 상세 절차는 미확정 상태로 두지 않습니다. 낭독 지시는 이 문서에서 관리하며 별도 멘트집을 만들지 않습니다.

행사 후 참여자·입회자는 **적용한 script·부속 문서의 고정 목록, 자신의 실제 수행/관찰 범위, 절차대로 수행했는지 여부, 일탈 또는 없음**을 식별해 확인 서명해야 합니다. [S06 수행 확인 서명](records/s06-verification.md#수행-확인-서명)과 [보류 시 확인 기록](records/hold-resume.md#보류중단-기록)은 이 연결을 갖추어야 하며 상세 양식 정리는 후속 작업입니다. S00에는 적용 절차와 실제 확인·일탈을 기록하고 아직 수행하지 않은 생성 작업에 서명하지 않습니다. 작업별 생성 계획·HSM 토큰의 전자 승인은 이 수행 확인 서명과 별개입니다.

## 진행 방법

- 진행자는 “S01.2, 생성 계획 승인”처럼 **단계·호출 번호·업무**를 소리 내어 알리고 현재 번호를 공용 진행판에 표시합니다.
- 각자는 자기 가이드의 같은 단계에서 번호를 찾습니다. **수행 / 대기 / 계속 관찰** 표시를 따릅니다. 단순히 다음 페이지를 넘겼다고 실행하지 않습니다.
- 단계별 공식 기록 원본을 정하고, 각 담당자가 호출 번호·본인·시각과 실제 결과를 해당 란에 기록합니다.
- 수행 확인 기록과 생성 계획/토큰의 전자 승인을 구분합니다. 전자 승인은 승인된 장치·앱에서 수행합니다.
- 값·검사 자료·출력 원문은 승인된 자료 묶음이나 작업 화면으로 제시합니다. 미확정 명령·설정으로 진행하지 않습니다. 중단은 누구나 요청할 수 있고 재실행은 임의로 하지 않습니다.

## 당일 사용할 설정과 실행 절차

- Administrator는 [시작 전 확인](preparation.md#시작-전-확인)과 승인본 목록을 확인하고 같은 버전의 가이드·설정·runbook·기록 양식을 제공합니다.
- [회차 목록](records/record-template.md)에 실제 기록지 사본을 연결합니다. 각 단계가 끝나면 그 기록을 닫고 다음 단계의 기록지를 엽니다.
- 단계 안에서는 **준비 → 사전 확인·개별 승인 → 실행 → 독립 검사·입회 기록 → 진행 판정** 순서를 지킵니다. 역할별 기록은 해당 담당자가 남기며 서명 기록은 덮어쓰지 않습니다.

## S00 시작 확인

**목적:** 수행 승인·참석자·환경·통제·기록·보호 준비를 확인하고 S01 진입 여부를 판정합니다. S00에서는 설정 변경·키 생성·CA 서명·생성 계획/토큰 승인을 수행하지 않습니다.

**진입 전:** Administrator는 행사 수행 승인 원문과 권한 근거, 승인본 묶음, 자료 1–5의 작성본·첨부, 기록 원본을 확보합니다. 제시 전 갱신 항목은 각 자료의 작성 시점표를 따릅니다. 승인 미확보나 필수 자료 누락을 현장 구두 확인으로 대체하지 않습니다.

**읽는 방법:** Administrator는 각 표의 지시를 위에서 아래로 한 행씩 읽고, 지시받은 사람의 수행·기록·완료 보고를 기다립니다. 자신에게 해당하는 행은 직접 수행합니다. 보고는 **“호출 번호, 역할, 수행·기록 완료”** 또는 **“호출 번호, 역할, 보류 요청, 항목·이유”**로 합니다. Witness는 전체 순서를 계속 관찰하며, 호출받지 않은 사람은 대기합니다. 필수 조건을 충족하지 못하면 정상 진행을 멈추고 아래 보류 절차를 따릅니다.

## S01 Root 키 생성

진입 조건: S00의 시작 선언·입회 기록이 끝나고 승인본·환경·배정에 미해결 변경이나 보류가 없어야 합니다. 상세 대조 기준은 각자의 S01 가이드, 실제 결과는 S01 기록지에 둡니다.

**전원: 자기 가이드의 S01과 해당 기록지를 확인하세요.** 진행자는 아래 번호를 한 번에 하나씩 부르고, 담당자 완료 보고와 필요한 검증 후 다음 번호로 갑니다. Independent Witness는 단계 시작부터 끝까지 관찰합니다.

| 호출 번호 | 지금 할 일·담당자 | 기록할 것 |
|---|---|---|
| **S01.1 생성 계획 제시** | **Crypto Officer**: 고정한 Root 생성 계획·내용표·작업 ID·해시·기한과 승인 설정·전체 명단·접근 배정을 제시하고 완료를 보고한다. 아직 키를 생성하지 않는다. | 기록지 S01 / Crypto Officer — 계획·제시 자료 참조 |
| **S01.2 계획 승인** | **Key Custodian 1, Key Custodian 2, Key Custodian 3**: 같은 계획을 각자 검토한다. 승인 참여자는 개인 승인키로 서명하고, 각자 승인/거부/미참여와 이유를 기록·보고한다. | 기록지 S01 / Key Custodians — 개인별 계획 승인 |
| **S01.3 승인 검사·접근 활성화** | **Administrator**: 가이드에 따라 승인·앱 검사·실행 입력 연결을 확인한 뒤 접근 활성화를 지시한다.<br>**Key Custodians 중 사전 배정된 접근 통제 담당자**: 본인 권한으로 활성화하고 결과를 보고한다. 미배정자는 대기한다.<br>**Administrator**: 실제 접근 범위·기한·입회를 검사한 후 실행 가능 또는 보류를 선언한다. | 기록지 S01 / Administrator — 승인 검사·활성화 지시·실행 가능 판정<br>접근 통제 수행 기록 — 배정자의 실제 조치 |
| **S01.4 키 생성 실행** | **Crypto Officer**: 실행 가능 선언과 현재 입력을 다시 대조하고 요청 시작을 기록한 뒤 승인된 요청을 실행한다. 응답·키 쌍 식별자·조회 자료와 추출한 공개키 파일을 보존·제시하고 완료를 보고한다. | 기록지 S01 / Crypto Officer — 실행 입력·요청/응답·공개키 자료·저장 결과 |
| **S01.5 결과 검증·보호 인수** | **Administrator**: 공개키 연결·속성·소유/공유·quorum·전체 노드 상태와 증거 저장을 독립 검사한다. S00에서 인수한 보호 책임의 이행과 백업 추적 상태를 확인·기록한다. | 기록지 S01 / Administrator — 독립 검사·보호·백업 추적 |
| **S01.6 임시 생성 접근 회수** | **접근 통제 담당자**: G01 배정과 승인 절차에 따라 임시 생성 접근을 회수하고 결과를 보고한다.<br>**Administrator**: 회수 후 거부·잔여 접근·유지 권한을 검사한다. 후속 서명에 필요한 지속 계정·소유/공유는 임의 삭제하지 않는다. | 기록지 S01 / 접근 통제 수행 기록 — 실제 회수<br>Administrator — 회수 검사·유지 권한 |
| **S01.7 단계 마감** | **Independent Witness**: 먼저 실제 관찰 범위·누락·이견을 보고한다.<br>**Administrator**: 결과·보호·회수·입회·기록을 확인해 S02 진행 또는 보류/중단을 선언한다.<br>**Independent Witness**: 실제 선언·시각을 기록하고 완료를 보고한다. **Administrator**는 그 후 다음 이동을 알린다. | 기록지 S01 / Independent Witness — 관찰·실제 선언<br>다음 단계 판정 — 판정·근거·다음 기록 |


- **통과 조건:** 유효한 계획 승인과 실행 입력 연결, 생성 순간 보호, read-back·coverage·지문 일치, 증거 저장·생성 접근 회수·보호 인계 및 실제 선언 기록 완료. 신규 키 백업 포함 완료는 S06에서 별도 확인합니다.
- **예외:** 승인 부족·불일치·입회 단절·결과 불명·저장 실패가 있으면 다음 호출을 멈추고 [S01 중단·재개 판단](guides/administrator.md#s01-중단과-재개-판단)을 적용합니다. 접근이 이미 열렸으면 정상 S01.6을 기다리지 않고 승인된 중단 절차로 회수·보호합니다.

## S00-R 백업·증거 대기 후 제한 재개

**Administrator**는 [가이드의 제한 재개 절차](guides/administrator.md#s00-r-제한-재개-절차)에 따라 이전 서명·보호 인수·접근 종료·변경·실제 참석과 관찰 조건을 확인하세요. 남은 S06 검사·S07 종료만 재개하며 새 키 생성·HSM 서명을 포함하지 않습니다. 확인 결과와 재개 판정은 전용 기록지의 재개 판단 기록에 작성하세요.

## 중단과 재개

발견자는 중단을 요청하고 **Crypto Officer**는 후속 요청을 멈추세요. **Administrator**는 [가이드의 중단·재개 판단](guides/administrator.md#중단과-재개-판단)을 적용하고 보류·재개 기록지에 상태·근거·보호 책임·판정을 기록하세요. 저장된 동일 서명 응답은 조립/검사만 복구하며, 생성 중단은 [S01 상태별 판단](guides/administrator.md#s01-중단과-재개-판단)과 구분합니다. 결과 불명에서는 재생성·재서명·삭제하지 않습니다. 필수 역할·입회·정족수·기록이 부족하면 다음 단계로 넘어가지 않습니다.

## 기록·확인 서명·최종 판정

S06은 수행·관찰 서명, S07은 인수·종료·최종 판정과 보관 확인입니다. 회차 목록에 각 실제 기록을 연결하고 세레모니 완료·운영 준비·제출/등록을 구분해 판정하세요. 승인된 별도 관리 작업이 있을 때만 관리 변경 기록지를 추가하세요.

# Key Custodian 2 담당자 가이드

## 처음 배정받았다면

**맡은 일:** 개인 승인키를 보호하고 생성 계획·서명 대상을 검토해 승인하거나 거부합니다. 세 승인자 중 Key Custodian 2이며 Crypto Officer가 1번을 겸합니다.

**먼저 할 일:** Administrator에게 본인 임명·교육 기준, 개인 계정/승인키 등록 담당자, 검토할 문서와 리허설 일정을 요청합니다.

**준비 순서:** 배정 확인 → 개인 계정·승인키 준비 → 승인 대상 읽는 방법 확인 → 승인 리허설 → 본인 준비 근거 제출.

**당일 흐름:** 본인 확인 → 작업별 계획·본문 검토와 개인 승인 → 실제 수행 범위 확인 → 본인 승인키 보관·인계 확인.

**역할 범위:** CA 키 생성·서명 실행과 독립 검증은 다른 담당자의 업무입니다. 개인키 공유·타인의 개인키 보관·대리 승인·과거 승인 재사용은 금지합니다. 접근/관리 작업은 별도 배정·권한이 있을 때만 수행합니다.

## 준비 순서

위에서 아래 순서로 준비합니다. 행사일·담당자·실제 마감일은 아직 미정이므로 Administrator와 확정합니다. ‘현재 상태’는 문서에 기록된 상태이며 본인의 준비 완료를 뜻하지 않습니다.

| 언제 | 내가 직접 할 일 | 받을 자료·요청할 사람 | 완료 근거 · 현재 상태 |
|---|---|---|---|
| 배정 직후 | 본인 임명·교육·겸임 범위 확인 | Administrator의 명부·교육 기준·일정 | 본인 명부·교육 근거 / 실명·일정 미정 |
| 리허설 전 | 승인된 방법으로 본인 승인키를 준비·독립 보관하고 CU/등록 공개키 연결 확인 | Administrator를 통해 계정/등록 담당자의 절차·등록 결과 확보(담당 미정) | 본인 CU·공개키 지문·등록 근거 / 계정·키·구현 미완료 |
| 리허설 전 | 계획·본문·키·기한을 어디서 확인하고 어떻게 승인/거부하는지 익힘 | Crypto Officer의 테스트용 계획/본문·승인 도구, Administrator의 고정 명부·기준 | 승인 대상 대조와 본인 서명/거부 연습 / 도구·시험 미완료 |
| 행사 전 | 배정된 리허설에서 본인 승인·거부·기록 수행. 접근 조치 배정이 있으면 함께 연습 | Administrator의 리허설 일정·역할/접근 배정, Crypto Officer의 실행 결과 | 본인 수행·미비점 해소 근거 / 미실시 |
| 행사 전 | 아래 S00 자료 2의 본인 근거를 제공하고 자료 4·5의 본인 확인 범위를 읽음 | Administrator의 명부 작성본, Crypto Officer의 통제 시험 자료 | 본인 정보·준비 근거 제출 및 대조 / 실제 자료 미확보 |

전체 환경 구축·시험 보고서 작성은 본인의 기본 배정이 아닙니다. HSM 관리자 겸임이나 접근 조치는 별도 배정을 확인합니다. 제시 직전 새 양식 작성은 없으며 본인 정보가 바뀌면 Administrator에게 알립니다.

## 누구에게 제출·보고하나

- **준비 자료·미정 사항·당일 결과:** Administrator(진행·검증 담당)에게 제출·보고합니다. 자료 검토와 단계 진행·종료 판정도 Administrator가 맡습니다.
- **사전 행사 수행 승인:** 별도 지정 승인권자가 맡으며 현재 미정입니다. Administrator에게 승인 근거를 확인받습니다.
- **작업별 생성·서명 승인:** 세 Key Custodian 중 서로 다른 2명 이상이 합니다. Witness의 관찰이나 진행자의 지시는 이 승인을 대신하지 않습니다.

**모르거나 불일치하면:** 승인하지 말고 이유를 기록해 Administrator에게 알립니다. 개인 승인 판단은 본인이 하며 다른 사람이 대신할 수 없습니다.

**용어:** CU는 개인 HSM 사용 계정, quorum은 필요한 승인 수(이번 생성·서명은 서로 다른 2명 이상), key-usage 토큰은 해당 키 사용 작업의 승인 대상입니다. 개인 승인키는 Root·First CA 키와 별개입니다. [용어·작업 번호](README.md#용어와-작업-번호)

**Root 키 생성** · [열 기록지](../records/s01-root-key.md#key-custodians)

1. **S01.1–.2 — 자료 대조·승인:** Crypto Officer가 제시한 Root 고정 계획·내용표·작업 ID·버전/해시·대상·알고리즘·보호 속성·소유/공유·전체 승인자 명단·CU/공개키·사용/관리 quorum·기한을 [승인 설정](../settings.md)과 대조합니다. 같은 계획의 원문을 열람할 수 없거나 불일치·만료가 있으면 승인하지 않고 사유를 보고합니다. 승인 참여 시 본인의 개인 승인키로 그 계획에 서명합니다. 생성 계획 서명은 HSM key-usage 토큰 서명이 아닙니다.
2. **개인별 기록·보고:** 승인/거부/미참여와 이유·대상 해시·서명 참조·시각을 `Key Custodians`의 **Key Custodian 2** 행에 작성합니다. “S01.2, Key Custodian 2, [승인/거부/미참여와 이유] 기록 완료”라고 보고합니다. 미참여를 승인으로 세지 않으며, 같은 계획에 서로 다른 2명이 유효하게 승인해야 실행할 수 있습니다. 본인이 승인했으면 앱 검사 결과의 본인 신원·등록 공개키·계획 해시 연결도 확인합니다.
3. **S01.3 — 접근 배정 확인:** 개인 승인 참여와 접근 통제 담당 배정은 구분합니다. 승인 배정표의 본인 권한·계정·범위·유효시간·검증된 절차를 확인하고, Administrator가 승인 검사 완료와 활성화 지시를 알린 뒤에만 본인 G01 조치를 수행합니다. 미배정자는 대기하며 다른 사람의 계정·자격증명을 쓰지 않습니다. 실제 계정·활성화 결과·범위·기한·시각·원문을 `접근 통제 수행 기록`에 작성하고 보고합니다. 배정 미정·활성화 실패·허용 범위 밖 접근이면 보류를 요청합니다. Administrator의 별도 실행 가능 선언 전에는 생성으로 넘어가지 않습니다.
4. **S01.4–.6 — 대기·회수:** 생성·검증 중에는 후속 요청을 하지 않습니다. S01.6 호출 시 G01 배정에 따른 G05만 수행해 실제 회수 대상·결과·유지 접근·원문·시각을 같은 접근 기록의 본인 행에 남기고 보고합니다. 회수 검사는 Administrator가 합니다. 후속 서명에 필요한 지속 계정·키 소유/공유를 임의 삭제하지 않습니다.
5. **중단·재개:** 계획 변경·불일치·입회 단절·접근 실패를 발견하면 즉시 중단을 요청합니다. 이미 열린 접근은 정상 S01.6을 기다리지 않고 배정된 중단 절차로 회수하고 실제 조치를 보류·재개 기록지에 연결합니다. 과거 계획 승인을 변경된 계획에 재사용하지 않습니다. 기존 키의 잔여 검사 재개 때도 승인된 범위와 본인 배정을 확인하며 새 생성 승인으로 취급하지 않습니다. 실제 참석·수행한 범위만 기록하고 S01.7 판정 이후의 다음 호출을 기다립니다.

**기록:** 계획 승인은 `Key Custodians`의 본인 행, 실제 G01/G05 조치는 `접근 통제 수행 기록`의 본인 행에 작성합니다. 미배정은 그 상태와 사유만 표시하며 타인의 조치·Administrator의 검사 결과를 대신 작성하지 않습니다. 기록 후 공용 원본을 돌려놓고 호출 번호와 완료/보류 사유를 보고합니다.

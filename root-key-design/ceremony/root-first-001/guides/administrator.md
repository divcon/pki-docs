# Administrator 담당자 가이드

## 처음 배정받았다면

**맡은 일:** 세레모니를 진행하고 실행 결과를 독립 검증합니다. 기록·키 보호·운영 인수도 맡습니다.

**먼저 할 일:** 본인을 배정한 담당자에게 행사 범위·일정, 임명/교육 근거, 행사 수행 승인권자와 지원 담당자 연락처를 요청합니다.

**준비 순서:** 권한·담당 확인 → 승인 문서·환경/시험 근거 취합 → 검증·인수 준비 → 리허설 → 수행 승인 확보.

**당일 흐름:** 준비 확인 → 승인·실행 순서 진행 → 결과 검증 → 전체 증거·백업 확인 → 인수·종료 판정.

**역할 범위:** 키 생성·서명 실행, 작업별 개인 승인, 다른 사람의 승인키 보관은 하지 않습니다. 행사 Administrator 직함만으로 HSM 관리자 권한을 얻지 않습니다.

## 준비 순서

위에서 아래 순서로 준비합니다. 행사일·담당자·실제 마감일은 아직 미정이므로 배정 요청자·지정 승인권자 및 해당 담당자와 확인합니다. ‘현재 상태’는 문서에 기록된 상태이며 본인의 준비 완료를 뜻하지 않습니다.

| 언제 | 내가 직접 할 일 | 받을 자료·요청할 사람 | 완료 근거 · 현재 상태 |
|---|---|---|---|
| 배정 직후 | 본인 임명·교육 확인. 5명 배정·직무 분리와 승인/지원 담당 확인을 요청 | 배정 요청자·각 참여자의 임명/교육 근거, 승인권한 근거 | 역할 명부·연락처·승인권한 참조 / 실명·권한·기한 미정 |
| 환경·시험 인수 전 | 구축·개발·상태 서비스·백업·시험의 실제 담당과 기한을 확인해 준비표에 연결 | 해당 지원 담당자에게 환경 인수서·구현 상태·작업 배정 요청(담당 미정) | 준비표 P03–P06의 담당·기한과 인수 자료 / 미완료 |
| 리허설 전 | [설정표](../settings.md)·[실행/독립 검사 절차](../runbook.md)·승인본 및 기존 시험 원문을 대조 | Crypto Officer의 환경/시험 자료, 지원 담당자의 도구·검사 기준·외부 확인 | 승인 버전·검사 방법·미비점 목록 / 실제 명령·외부 근거 미완료 |
| 리허설 전 | 본인 검증 환경·기록 원본·보관/보호·인수 계획 준비 | 배정된 지원 담당자의 조회 권한·백업/복구/상태 서비스 근거 | 본인 독립 검사·기록/조회 가능, 인수 책임 식별 / 준비·시험 미완료 |
| 행사 승인 전 | 테스트 키 리허설에서 진행·검증·보류·기록·인수 역할 수행. 미비점 재검토 | 전원 참여 결과, 배정된 시험 수행자의 보고서·수정/재시험 원문 | 필수 시험·리허설의 미비점 해소 근거 / 미실시 |
| 행사 전 | 아래 S00 담당 문서를 완성하고 수행 승인 확보·승인본 배부 | 지정 승인권자의 수행 승인, 전원의 준비 자료 | 수행 승인·동일 승인본 배부·시작 조건 확인 / 미승인 |

직접 인프라를 구축하거나 모든 시험을 대신 수행하는 배정은 아닙니다. 미배정 작업은 담당·권한·기한을 먼저 확인하고, 본인의 독립 검증 범위를 지킵니다. 준비 현황은 [P02–P07](../preparation.md#먼저-정할-사항)에 연결합니다.

## 누구의 승인·확인을 받나

- **사전 행사 수행 승인:** 지정 승인권자에게 받습니다. 승인권자·권한 근거·승인 기록은 현재 미정/미확보입니다.
- **자료 검토·단계 진행·종료 판정:** 본인이 근거를 확인하고 기록합니다. 본인이 작성·인수한 부분은 다른 사람이 독립 검증했다고 표시하지 않습니다.
- **작업별 생성·서명 승인:** 세 Key Custodian 중 서로 다른 2명 이상이 합니다. 진행 지시로 이 승인을 대신할 수 없습니다.
- **문제가 생기면:** 진행을 보류하고 원인·담당·남은 조건을 기록합니다. 재개는 필요한 재승인과 지정된 재개 승인권자의 근거를 확인한 뒤 판단합니다.

**읽기 안내:** [S00 준비 문서](#행사-전에-준비할-문서) · [실행/검사 절차](../runbook.md) · [용어](README.md#용어와-작업-번호). 실제 환경·명령·시험·승인이 미완료이므로 현재 가이드만으로 운영 행사를 시작하지 않습니다.

### 진행·보류 기준

- 낭독과 수행 순서는 [script의 S00](../script.md#s00-시작-확인)를 따릅니다. S00.1에 적용 script·부속 문서 승인 목록을 기록하고 S00.5에 그 절차와 실제 수행의 일치 여부·일탈을 연결합니다.
- S00.2 본인 확인 순서: Crypto Officer → Key Custodian 2 → Key Custodian 3 → Witness → Administrator. 실행/검증 분리, 세 보유자의 서로 다른 신원, Witness 미겸임을 확인합니다.
- 필수 근거·시험·역할·입회·로그/저장 또는 보호 책임이 미확인이면 보류합니다. B00 인수와 모든 시작 조건을 충족해야 통과입니다.
- 자료가 바뀌면 이전 제시본을 보존하고 새 버전·변경 승인·원문으로 재검토합니다. 기록지에 새 결과를 추가하고 이전 판정은 유지합니다.
- S00.5에서 “S01 시작” 또는 “S00 보류/중단, 사유 …”를 선언합니다. Witness의 실제 선언 기록 완료 후 이동합니다. S01의 생성 승인은 별도로 받습니다.

**Root 키 생성** · [열 기록지](../records/s01-root-key.md#administrator)

1. **S01.1 — 진입·자료 제시:** S00의 실제 시작 판정과 Witness 기록 완료를 확인합니다. 승인본·환경·명단·배정 변경이 있으면 영향 검토와 필요한 재승인 전 진행하지 않습니다. Crypto Officer가 제시한 고정 계획·내용표·해시·작업 ID·기한, 승인 설정·전체 명단·접근 배정 및 원문을 참여자가 볼 수 있는지 확인합니다. 자료가 빠지면 승인 호출을 멈춥니다.
2. **S01.2 — 개인별 보고:** 각자의 승인/거부/미참여와 이유를 받습니다. 서로 다른 2명 이상의 유효한 승인이 필요하며 1+2·1+3·2+3을 모두 허용합니다. Crypto Officer의 실행은 승인 수에 포함하지 않습니다. 거부·이견은 사유와 해소 판단을 기록하며 다른 두 명의 승인이 있다는 이유만으로 불일치나 중단 요청을 무시하지 않습니다. 미참여를 거부나 승인으로 바꾸지 않습니다.
3. **S01.3 — 승인 검사 후 활성화:** 아래 기준을 통과하면 실제 승인자 조합·앱 검사 근거와 활성화 지시·시각을 기록하고, 사전 배정된 접근 통제 담당자를 호출합니다. 배정 근거·행사 역할과 별도 권한·실제 수행 계정이 확인되지 않으면 활성화하지 않습니다. 담당자의 조치 결과를 받은 뒤 허용 계정·호스트·코드·파라미터·유효시간·잔여 경로를 승인 범위와 대조합니다. Witness가 관찰 가능하고 모든 검사가 통과할 때만 “S01.3 검사 완료, 승인된 Root 요청의 실행이 가능합니다”라고 선언·기록합니다. 실패 시 생성 요청을 금지하고 이미 열린 접근은 중단 절차로 회수합니다.
4. **S01.4 — 실행 보고:** Crypto Officer의 현재 입력 재대조·요청 시작·응답 저장·공개키 자료 제시 완료를 받습니다. 응답 유실·부분 성공·저장 실패·입회 단절이면 다음 정상 호출을 멈추고 아래 상태별 판단을 적용합니다. 성공 보고만으로 결과를 통과시키지 않습니다.
5. **S01.5 — 독립 검사·보호:** G03/G04의 승인된 방법으로 정확한 공개키/개인키 식별자·클래스·P-384 곡선·연결을 확인합니다. Crypto Officer가 제시한 SPKI DER 공개키의 연결과 SHA-256 지문을 독립 검사합니다. 서명 전용·추출 금지·보호/잠금 속성, 소유/공유·사용 quorum 2·승인된 관리 quorum과 전체 노드 coverage·지연을 승인값과 대조합니다. 부분 반영은 통과시키지 않습니다. 원본 응답·공개키·독립 조회 증거의 저장·조회 성공과 E01 연결을 확인합니다. S00에서 인수한 생성 직후 보호 책임은 검사 완료 전에도 유지하며, 책임자·보호 상태·B01 백업 추적 대상·담당·다음 확인 시점을 기록합니다.
6. **S01.6 — 회수 검사:** G01 배정자가 G05 회수 결과를 기록·보고하면 사전 검증된 절차로 직접 재접속·추가 생성 경로의 거부와 잔여 접근을 검사합니다. 유지할 서명·관리 권한에는 승인 근거·담당·범위를 연결합니다. 이후 필요한 지속 계정·소유/공유는 임의 삭제하지 않습니다. 회수 실패이면 후속 서명을 금지하고 보호·보류 상태를 인계합니다.
7. **S01.7 — 선언과 이동:** Witness의 실제 관찰 범위·누락·이견을 먼저 받습니다. 승인·생성 결과·보호·회수·증거·이견 처리를 확인해 S02 진행 또는 보류/중단을 선언하고 근거·시각·다음 실제 기록을 남깁니다. Witness가 실제 선언을 기록해 완료를 보고한 뒤 다음 이동을 알립니다.

### S01 승인·실행 입력 대조

| 확인 대상 | 대조 기준과 보류 조건 |
|---|---|
| 고정 계획과 승인본 | 계획 ID·버전/해시·내용표·대상 환경·Root 용도·알고리즘·보호 속성·소유/공유·사용/관리 quorum이 승인 설정과 일치. 자료 누락·불일치면 보류 |
| 승인 신원·서명 | 고정 명단의 서로 다른 2명 이상이 같은 계획에 서명. 세 보유자의 신원·CU·앱 공개키·등록키 연결을 대조. 0/1명·동일인 중복·명단 밖 승인·등록키 불일치로 통과 불가 |
| 앱 검사 원문 | 승인된 앱/설정 버전, 계획 해시·작업 ID·전체 명단·실제 승인자·검사 시각·기한·미사용 작업 확인을 대조. 요약 성공 표시만으로 원문을 대신하지 않음 |
| 실제 실행 입력 | 요청 대상·계정·코드/설정·생성 옵션이 앱이 검증한 계획에 연결됨. 계획/명단 변경·만료·작업 재사용 또는 직접 우회 경로가 있으면 실행 불가. 실행자는 S01.4 직전에도 다시 확인 |

**기록:** `Administrator`의 S01.3 승인 검사·활성화 지시·실행 가능 판정, S01.5 독립 검사·보호·백업, S01.6 회수 검사와 `다음 단계 판정`을 작성합니다. 접근 담당자의 원본 조치 기록은 참조로 연결하고 대신 작성하지 않습니다.

### 단계 판정 기준

- **통과 조건:** 유효한 계획 승인·실행 입력 연결, 생성 순간 보호, read-back·coverage·지문 일치, 증거 저장·생성 접근 회수·보호 인계와 실제 선언 기록 완료.
- **백업:** S01에서는 추적과 보호 상태를 확인하고 실제 신규 키 포함 완료는 S06에서 판정합니다. 백업 READY만으로 포함 완료라 적지 않습니다. 승인된 보호/대기 계획이 충족되지 않거나 저장에 실패하면 보류합니다.
- **중단:** 승인·옵션·권한 불일치, 부분 성공·결과 불명, 입회 단절·필수 증거 누락, 접근 회수 실패. 상태 조사나 보호 조치가 재생성·삭제 허가는 아닙니다.

### S01 중단과 재개 판단

모든 경우 Crypto Officer는 후속 요청을 멈추고 원본을 보존합니다. 본인은 마지막 확정 상태·미확인 범위를 기록하고 보호 책임을 유지합니다. 접근이 열렸으면 G01 배정자가 승인된 G05/X01 중단 절차로 회수하고 본인이 결과를 검사합니다. 정상 S01.6까지 기다리지 않습니다. 판단·조치·실제 수행자·시각은 [보류·재개 기록지](../records/hold-resume.md)에 남깁니다.

| 중단 당시 상태 | 판단과 재개 범위 |
|---|---|
| 자료/승인 부족·거부·명단/입력 불일치, 요청 전 미실행 입증 | 부족 자료·이견·변경을 해소하고 필요한 계획 재승인과 접근/입회 조건을 확인. 재개 승인권자의 승인 및 복귀 호출을 기록한 뒤 해당 S01.1–.3부터 다시 확인. 이전 실행 가능 선언만으로 S01.4에 바로 진입하지 않음 |

## 보류와 재개

후속 요청을 중단시키고 마지막 상태·원문·키/증거 보호를 확보합니다. 판정 결과는 [보류·재개 기록지](../records/hold-resume.md)에 기록합니다. 기술적 상태 판정에는 [작업 원장과 장애 판정](../runbook.md#작업-원장과-장애-판정)을 적용합니다.

### S00-R 제한 재개 절차

1. **Administrator**는 이전 서명 목록·대기 사유·custody·임시 접근 종료 기록과 미완료 항목을 대조합니다. 새 키 생성이나 HSM 서명을 포함하지 않는 재개인지 확인합니다.
2. **Administrator**는 필요한 환경·권한·데이터의 동일성, 대기 중 변경과 사고 여부, 백업·로그 수집·기록 저장 상태를 확인합니다. 역할별 유효 자격과 승인된 관찰 범위를 확인하고, 실제 조회에 Crypto Officer나 다른 담당자가 필요하면 그 사람의 참여·최소 접근을 기록합니다. Key Custodian 2·Key Custodian 3·Independent Witness의 재참석 필요 여부는 재개 작업과 승인된 입회 조건으로 판단합니다.
3. **Administrator**는 “이전 생성·서명 기록을 유지하고 S06의 남은 백업·증거 검사와 S07 종료만 재개합니다”라고 승인합니다. S00의 Root 생성 시작 선언이나 S01–S05를 반복하지 않습니다. 범위가 달라지면 제한 재개를 취소하고 별도 변경 승인을 받습니다.
4. **Administrator**는 회차·참석·조회 접근·검사 범위·재개 승인을 E00-RESUME에 기록합니다. 후속 수행자들은 추가 기록에 자신의 범위만 확인 서명합니다.

### 중단과 재개 판단

1. 발견자는 단계와 사유를 알리고 Crypto Officer는 후속 생성·서명 요청을 중단합니다. Administrator는 시각·마지막 명령·현재 결과를 기록합니다.
2. Administrator·Crypto Officer는 생성 키 조회와 서명 결과 복구를 구분합니다. 서명은 [원장 상태표](../runbook.md#작업-원장과-장애-판정)와 내구 저장된 실행기 요청·응답을 확인합니다. HSM/CloudWatch 관리 로그만으로 해당 본문의 서명 성공·미실행 또는 서명값 복구를 단정하지 않습니다. 상태 확인 전 재실행·삭제하지 않습니다.
3. Administrator는 키·백업·증거 보호를 유지하고 사고 의심 시 {{사고_절차}}로 넘깁니다.
4. 저장된 동일 서명 응답은 Q08만 재개하며 새 HSM 서명을 요청하지 않습니다. 요청 전 미실행이 입증된 작업은 필요한 새 승인·세션과 서명 작업의 새 토큰을 확보하고 {{재개_승인권자}}가 실행을 승인합니다. S01 생성 중단은 [상태별 판단](#s01-중단과-재개-판단)에 따라 기존 키 조사·잔여 작업과 새 생성을 구분합니다. 결과 불명은 별도 정책 판단으로 넘깁니다. S00-R은 생성·서명 단계가 끝난 뒤 남은 S06 백업·증거 검사와 S07 종료에만 적용합니다.
5. 해소되지 않으면 중단 상태로 인계합니다. 유지·폐기·재생성은 {{판단_책임자와_절차}}에 따라 별도 승인합니다.


### 별도 관리 작업

정상 S00–S07에 관리 변경을 임의로 추가하지 않습니다. B00 초기 인수와 잠금·폐기 조건은 S00/E00에 연결합니다. 실제 승인된 별도 관리 작업이 있을 때만 [관리 실행 절차](../runbook.md#관리와-별도-통제-절차)의 역할·계정으로 수행하고 [관리 변경 기록지](../records/management-change.md)를 연결합니다.

네이티브 quorum 지원 작업과 키 생성·삭제·AWS API·호스트/코드·등록키 변경의 별도 통제를 구분합니다. 승인 수 충족은 잠긴 속성 해제나 금지 암호 연산의 허가가 아닙니다. 실제 관리자 실행자·승인자·검증자·입회자의 수행/관찰 범위와 확인 서명을 취합합니다.

## 기록 준비와 보관

행사 전에 회차별 기록 사본과 회차 목록을 승인된 기록 저장소에 준비합니다. `session-01-s00-start.md`처럼 회차를 식별하고 이전/다음 링크를 실제 사본으로 연결합니다. 인적 사항·서명·민감 로그를 문서 저장소로 자동 반입하지 않습니다.

종이 운영 시에는 단계별 공용 원본 한 묶음을 준비하고 행사·회차·원본 묶음 번호를 부여합니다. 각 담당자가 본인 칸에 직접 기록하고, Administrator는 취합·검증·판정을 맡습니다. 타인의 승인·입회 확인을 대신하지 않습니다. 개인 책자 메모는 공식 기록으로 집계하지 않습니다. 인쇄 묶음의 최종 제작은 별도 준비 일정에 따릅니다.

실제 값·전자서명·요청/응답·로그·검사 원문은 증거 번호로 연결하고 종이 원본과 전자 자료를 대조해 인수·보관합니다. 종이 확인 서명으로 앱/HSM 전자서명을 대신하지 않습니다. 수행 전 빈칸이나 미확인·보류·중단을 완료/통과로 표시하지 않습니다.

승인된 스크립트·가이드·설정·runbook을 수행 기록으로 수정하지 않습니다. 서명 대상 목록에는 자기 해시나 이후 서명 파일을 포함하지 않고 서명은 대상 목록을 식별하도록 연결합니다. 서명된 기록·고정 사본은 수정하지 않으며, 후속 목록이 이전 목록·서명·추가 기록을 연결하게 합니다.

각 단계의 판정 후 다음 단계 또는 보류·재개 기록을 연결합니다. S07의 최종 판정과 그 보관 확인이 끝난 뒤 회차 목록을 갱신합니다. [최종 보관 기준](../settings.md#최종-보관-기준)을 적용합니다.

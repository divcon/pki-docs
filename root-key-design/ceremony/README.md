# Root·공용 First ICA Ceremony

Root와 공용 First ICA의 키를 새로 만들고 Root 자기서명 인증서와 First 인증서를 발급한다. 두 개인키는 Global CloudHSM에 보관한다. 하위 Issuing ICA는 이번 생성·감사 범위 밖이며 이후 관리·발급 대상으로 유지한다.

현재는 수행 스크립트 초안이다. 키 생성 통제·운영 파라미터·담당자·도구 검증이 남아 있다. 확정 범위는 [요구사항](../requirements.md)을 따른다.

준비를 시작할 때는 [준비 체크리스트](preparation-checklist.md)를 먼저 읽는다. 스크립트는 [샘플](ceremony-script-sample.md)에서 완성 형태를 확인하고, [템플릿](ceremony-script-template.md)을 복사해 작성한다. 각 항목의 의미와 작성·검토 방법은 [작성 가이드](script-writing-guide.md)에 둔다.

## 전체 순서

1. 템플릿을 복사해 행사별 승인본을 만든다. 기술 참고와 CloudHSM 절차를 반영하고 설정·담당자·실제 명령·입력값·기대 결과·중단 조건을 채운다.
2. 계획을 승인하고 테스트 키로 전체 절차를 연습한다.
3. 당일 참여자·환경을 확인한 뒤 입회·기록을 시작한다.
4. Root 키를 생성한다.
5. Root 생성 결과를 검사하고 키 식별자·공개키·생성 기록을 확인한다.
6. Root 자기서명 인증서를 발급하고 검사한다.
7. First 키를 생성하고 같은 방식으로 생성 결과를 검사한다.
8. First CSR을 생성한다.
9. Root 키로 First 인증서를 발급한다.
10. 전체 결과와 신규 키·최종 설정의 실제 백업, 원장·증거 백업을 확인한다. 대기 중이면 보호 인계·임시 접근 종료 후 보류하고 후속 검사만 재개한다.
11. 참여자·입회자가 전체 수행 기록에 확인 서명을 남긴다.
12. 운영 담당자에게 인계한다.
13. 임시 권한과 세션을 종료한다.

**당일 실행 기준은 템플릿으로 작성한 행사별 승인본과 그 승인본이 버전·해시로 고정한 부록이다.** 키 생성·인증서 발급 기술 참고 문서를 별도 실행 순서로 사용하지 않는다. CloudHSM 설정과 실제 명령은 승인본 확정 전에 함께 검증한다. 단계별 증거는 수행 시점에 남기고 각자의 수행·관찰 범위를 확인 서명한다.

기술 참고는 작업 종류별로 나뉘어 있으므로 행사 승인본은 위 순서로 작성한다. 특히 키 생성 직후 검사와 생성 접근 회수를 Root와 First 각각 수행한다. 세 번의 서명에는 각각 별도 본문 승인·quorum 토큰·실행·응답 보존·검사가 필요하다.

Ceremony 완료, 운영 준비, 감사, Trust List 등록은 각각 확인한다. 생성 관련 미정 사항은 [키 생성](key-generation.md#남은-결정), 발급·운영 인계 관련 사항은 [인증서 발급](certificate-issuance.md#남은-결정과-운영-인계)에서 관리한다.

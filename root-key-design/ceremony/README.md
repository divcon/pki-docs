# Root·공용 First ICA Ceremony

Root와 공용 First ICA의 키를 새로 만들고 Root 자기서명 인증서와 First 인증서를 발급한다. 두 개인키는 Global CloudHSM에 보관한다. 하위 Issuing ICA는 이번 생성·감사 범위 밖이며 이후 관리·발급 대상으로 유지한다.

현재는 수행 스크립트 초안이다. 키 생성 통제·운영 파라미터·담당자·도구 검증이 남아 있다. 확정 범위는 [요구사항](../requirements.md)을 따른다.

|---|---|---|
| [키 생성](key-generation.md) | 생성 계획·리허설·참여자·환경 확인, Root·First 키 생성, 입회·기록 | HSM 키 쌍, 공개키·키 식별자, 생성 검사·입회 기록 |
| [CA 인증서 발급](certificate-issuance.md) | Root 자기서명, First CSR·인증서 발급, 결과 검증, 전체 기록 확인 서명·인계·종료 | Root·First 인증서, 발급·최종 수행 기록 |
| [CloudHSM 추가 옵션](cloudhsm-options.md) | 수행 절차 확정 후 검토할 구현 설정 | 키 속성·사용자·quorum 등 설정 후보 |

## 전체 순서

1. 두 실행 문서의 설정·담당자·명령·입력값·기대 결과·중단 조건을 채운다.
2. 계획을 승인하고 테스트 키로 전체 절차를 연습한다.
3. 당일 참여자·환경을 확인한 뒤 입회·기록을 시작한다.
4. Root 키를 생성한다.
5. First 키를 생성한다.
6. 생성 결과를 확인하고 키 식별자·공개키·생성 기록을 발급 절차에 넘긴다.
7. Root 자기서명 인증서를 발급한다.
8. First CSR을 생성한다.
9. Root 키로 First 인증서를 발급한다.
10. 전체 결과를 확인한다.
11. 참여자·입회자가 전체 수행 기록에 확인 서명을 남긴다.
12. 운영 담당자에게 인계한다.
13. 임시 권한과 세션을 종료한다.

두 실행 문서는 **하나의 ceremony 수행 스크립트를 나눈 구성**이다. 실행 전 두 문서의 버전을 고정하고 같은 작업 ID로 결과를 연결한다. 단계별 증거는 수행 시점에 남기며 최종 확인 서명은 전체 기록을 대상으로 취합한다.

Ceremony 완료, 운영 준비, 감사, Trust List 등록은 각각 확인한다. 생성 관련 미정 사항은 [키 생성](key-generation.md#남은-결정), 발급·운영 인계 관련 사항은 [인증서 발급](certificate-issuance.md#남은-결정과-운영-인계)에서 관리한다.

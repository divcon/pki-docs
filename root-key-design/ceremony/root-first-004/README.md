## 002에서 가져온 것

- TBS 생성 → 본문 해시 확인 → 새 key-usage 토큰 → `crypto sign --approval` → 조립하는 서명 경로
- 키 사용 Quorum 2, 공유 사용자 승인, 서명마다 새 토큰
- 부록 A 프로파일 값(Root AKI 포함, ICA는 AIA만 사용, CSR 요청 확장, 20년/5년)
- 서명 반복 금지, 조립만 복구하는 규칙, 결과를 알 수 없으면 중단하는 규칙
- IW 독립성 기록, 신뢰 역할 적격성 확인, 준수 여부를 표시하는 참여자 서명
- 승인본 해시 고정, 미결 항목이 있으면 시작하지 않는 규칙(부록 D)

## 남은 위험

- CO는 혼자 HSM에 로그인해 새 키를 만들 수 있다. 다만 CA 키의 사용·공유·속성 변경과 새 키의 인증(Root 서명)에는 모두 KC 2명의 승인이 필요하다. 오프라인화 이후에는 HSM 자체가 없다.
- **CO는 혼자 CA 키를 HSM에서 지울 수 있다.** AWS의 관리 Quorum(`key-management`)에 key delete가 포함되지 않기 때문이다. 키를 쓸 수는 없으므로 가용성 위험이다. 행사 중에는 입회자가 지켜보고, 5.8 이후에는 HSM이 없으며, 만료 없는 백업(원본·off-site)에서 복원할 수 있다.
- KC 2명이 공모하면 각자의 `cu_kcN` 계정으로 CO 없이 키를 사용할 수 있다. CP의 2인 요건은 충족한다. 오프라인화 이후에는 IAM-Op의 HSM 생성이 필요하므로 실제 필요 인원은 3명이다.
- `{{tool}}`·`{{verifier}}` 개발과 리허설(부록 D)이 일정을 좌우한다.

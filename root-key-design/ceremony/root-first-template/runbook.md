# Root와 First ICA 세레모니 — 실행 절차

작성 중 · 실제 실행 명령과 도구는 아직 채워지지 않았습니다. 이 문서의 CMD/G/Q/B/X는 절차 식별자이며 그 자체로 실행 가능한 명령이 아닙니다.

[메인 스크립트](script.md)의 순서로 호출합니다. 입력값은 [설정](settings.md), 수행 결과는 [회차별 기록](records/record-template.md), 원문 출력은 [증거 목록](evidence-index.md)으로 연결합니다.

## 명령을 작성할 때

각 실행 정의에 다음 내용을 함께 적습니다. 상세 명령을 별도 파일에서 관리하면 경로·버전·해시를 [승인본 목록](preparation.md#승인본-목록)에 추가합니다.

| 항목 | 명령별로 작성할 내용 |
|---|---|
| 실행 위치·담당 | 호스트·계정·담당자, 필요한 사전 승인과 세션 유지 방식 |
| 실행 내용 | 실제 명령 또는 절차 파일·옵션·정확한 입력 경로 |
| 실행본 식별 | 코드·CLI·설정·검증 도구 버전과 파일 해시 |
| 결과와 검사 | 출력 위치·형식, 종료 상태, 기대값·독립 검사 방법 |
| 실패 처리 | 중단 조건, 결과 불명·부분 성공·저장 실패의 처리 |
| 증거 | 요청·응답·승인·검사 파일의 증거 ID와 기록 위치 |

## 공통 서명 절차 Q01부터 Q08

승인된 [CloudHSM 실행 부록](../cloudhsm-options.md)의 Q01–Q08과 아래 작업별 입력을 사용합니다. 부록·명령 파일의 승인 버전과 해시: {{CloudHSM부록과_실제명령_고정참조}}.

| 단계 | 서명 키 | 고정할 서명 대상 | 실행 작업 |
|---|---|---|---|
| S02 | Root | TBSCertificate DER, {{Root_본문경로}} | CMD-02 → Q01–Q08 / CMD-03·04 |
| S04 | First | CertificationRequestInfo DER, {{First_CRI경로}} | CMD-06a → Q01–Q08 / CMD-06b·07 |
| S05 | Root | TBSCertificate DER, {{First_본문경로}} | CMD-08 → Q01–Q08 / CMD-09·10 |

1. **Q01 — O/V/A/B:** 작업 ID·발급 serial 예약과 중복 검사를 원장에 남깁니다. 정확한 DER·내용표·증거용 SHA-256·서명용 알고리즘·raw/digest 선택·키 지문·프로파일·기한을 고정하고 A/B가 본문 승인을 기록합니다. CSR에는 serial 대신 CSR 작업 ID를 사용합니다.
2. **Q02 — O/V:** 대상 계정·클러스터·키 소유/공유·사용 quorum·승인키 등록을 확인합니다. O가 현재 CLI 로그인 세션을 유지하며 기록용 세션 식별자를 작업과 연결합니다.
3. **Q03 — O:** 해당 키의 key-usage 토큰을 생성합니다. service·key-reference·토큰 식별 해시·생성/만료시각·세션·작업 ID를 기록하고 승인된 전달 경로로 보냅니다.
4. **Q04 — 각 승인자:** 받은 토큰과 본문 승인 묶음의 작업·키·기한을 대조한 뒤 본인에게 등록된 별도 승인키로 토큰에 서명합니다. O가 승인 서명을 취합합니다. 실제 서명 입력 변환은 고정 명령 파일을 따릅니다.
5. **Q05 — V:** 승인자 개인 계정·등록 공개키·허용 집합·필요 수와 만료/세션 유효성을 검사합니다. 같은 사람의 복수 계정이나 허용하지 않은 자기승인으로 수를 채우지 않습니다. 조건 미달은 실행을 거부합니다.
6. **Q06 — O/V:** 현재 DER·digest·서명 키가 승인값과 같은지 재대조합니다. O의 명시적 실행 지시와 `요청 시작`을 내구 저장한 뒤 승인 토큰을 `--approval`로 전달해 해당 ECDSA 작업을 실행합니다. 원본 응답의 보존 실패를 감지합니다.
7. **Q07 — O/R:** 반환한 서명값을 포함한 응답을 통제된 저장소에 즉시 보존하고 응답 해시·명령 상태·세션·토큰의 사용/실패 상태를 기록합니다. 성공 토큰을 재사용하지 않으며 실패 응답만으로 재사용 가능하다고 판단하지 않습니다.
8. **Q08 — O/V/R:** raw r||s와 ASN.1 DER 서명 형식 변환 후 고정 본문으로 인증서/CSR을 조립합니다. 독립 도구로 서명·본문 바이트·키·프로파일을 검사하고 산출물과 원장·증거를 확정 저장합니다. 원본 응답이 이미 있으면 이 단계부터 복구하며 HSM 서명을 반복하지 않습니다.

본문 승인과 토큰 승인은 별도 기록이며 작업 ID로 연결합니다. 토큰 서명만으로 본문 바이트의 불변성이 보장된다고 간주하지 않습니다. 어느 단계든 연결 단절·만료·입력 변경·기록 실패는 중단하고 아래 상태표로 판정합니다.

## 작업 원장과 장애 판정

원장 위치·쓰기 권한·내구 저장 방식·조회 명령·중복 실행 잠금: {{원장_계약과_시험}}. 발급 확정 시점·동일 결과 재저장/재조립과 새 서명의 구분: {{발급_경계와_재개_정책}}.

| 상태 | 남길 증거 | 실패 시 허용할 처리 |
|---|---|---|
| 준비·승인 | 작업 ID, serial 예약, DER·키·프로파일·승인·해시 | HSM 요청 전임이 입증되면 입력 수정·필요한 재승인 후 실행 |
| 요청 시작 | 같은 작업의 실제 명령·입력·세션·토큰 참조와 실행 전 intent | 전송/응답 여부 불명이면 `결과 불명`으로 전환 |
| 응답 보존 | 원본 서명값·응답·해시·저장 확인 | 같은 응답으로 변환·조립·검사를 재개. 새 HSM 서명 금지 |
| 조립·검증 | 산출물·본문 일치·독립 검사 | 원본 응답으로 동일 산출물 복구; 불일치는 배포 보류·사고/정책 판단 |
| 발급 저장 | 인증서·serial·키 연결·폐지 상태·검사·승인·증거 확정 | 동일 결과의 저장 완료 여부를 조회하고 중복 발급 차단 |
| 결과 불명 | 마지막 확정 상태, 요청/응답 증거, 복구 불가 범위 | 로그 부재를 미실행으로 보지 않음. 자동 재서명/재생성 금지, 격리·조사·별도 정책 승인 |

승인과 응답을 디스크에 쓴다는 사실만으로 모든 장애 구간이 없어지지는 않습니다. 요청 전·전송 후·응답 수신 전·저장 중 장애 시험 결과와 남는 불명 구간: {{장애_실증과_불명상태_책임자}}.

## 공통 부록 연결

[CloudHSM 절차](../cloudhsm-options.md)의 B00·G01–G05·Q01–Q08·B01·X01을 이번 행사의 실제 명령과 연결합니다. B00은 [준비 인수 기록](preparation.md#준비와-승인-자료), 생성·서명·백업·종료 호출은 위 실행 작업에 대응시킵니다. 부록도 승인 시 버전과 해시를 고정하며, 승인 후 수정된 공통 문서를 그대로 실행하지 않습니다.

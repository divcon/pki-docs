우리 플랫폼의 루트키를 만들거야. 여러서 서비스에서 인증서를 만들어야 하는데 이거에 대한 ICA 를 서명할 루트키야.

서비스 혹은 기기 플랫폼 별로 인증서를 사인 할 때만 사용 할거야.

1차 대상은 C2PA 인증서야.

C2PA 인증서의 루트가 요구하는걸 만족해야 해. Root 까진 만족 못하더라도 최소한 C2PA First ICA 는 C2PA 가 요구하는 요청사항을 전부 만족해야 해.

그런데 C2PA 인증서 루트의 요구사항이 거의 Root 를 관리하는 표준이 아닌가 싶은데.. 만약 표준과 가깝다면 그냥 이걸 많이 참조 할래.

근데 이건 기기 플랫폼 별로 ICA 가 따로 나갈거라서 Root key -&gt; C2PA First ICA (Trust list 등록)-&gt; Phone / TV C2PA ICA 방식으로 할거야.

TSA 용이 따로 필요한건지는 모르겠어 결정해야 해. 아마 TSA 용도 First ICA 를 만들고 Trust list 에 등록 한 뒤 Phone 과 TV 에 발급하는 방식으로 가도 될것 같아.

private key 는 AWS Cloud HSM 에서 관리할거야. Global 과 CN 이 동일하게 가져갈거고 매번 실시간으로 동작하는게 아니기 때문에 람다에 넣는게 어떤가 싶어.

root key 로 ICA 를 사인하거나 first key 를 통해 ica 를 사인 할 때 두 사람 이상의 권한을 가진 사람이 서명 해야 해. 이걸 어떻게 해야 할지 잘 모르겠어.

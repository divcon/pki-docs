## 기록 방식

- 한 번에 한 주제를 다루며, 기존 확정 사항은 배경으로 연결하고 남은 결정에 대해 질문한다.

## Q05 — Root만 탑재하고 서버가 First 신뢰를 관리하는 방식

- 일시: 2026-09-21 16:26 KST
- 관련 설계: S01, S06, S07, S09
- 상태: 검토 중 · 단말 구현과 오프라인 요구 확인 대기
- 검토 기록: [RV-001 — Root 탑재와 서버 관리](reviews/001-first-ica-structure.md#root-only-server)

**사용자 입력**

> 근데 first 를 단말에 박아 넣으려면 self signed 인 root 도 같이 박아 넣긴 해야 해.
> 서버에서 trust anchor 로 first 를 관리하는 서버를 만들고 root 만 박아 넣는 방식도 있나??

**답변·반영:** 가능한 구조다. 다만 First를 직접 신뢰 앵커로 쓰는 검증기에는 상위 Root 탑재가 일반적으로 필수인 것은 아니므로, 사용자의 설명은 현재 단말 구현의 제약인지 확인할 입력으로 남겼다. 서버가 인증서만 제공하면 단말의 앵커는 Root이며 First는 중간 인증서다. 인증된 목록을 받아 First를 앵커로 설정하는 방식과, First를 앵커로 쓰는 서버에 검증을 맡기는 방식도 구분해 RV-001에 추가했다.

**제안의 범위:** 단말이 직접 검증하면서 중앙에서 허용할 First를 관리하려는 목적이면 인증된 목록 배포를 후보로 삼는다. 단순 체인 확보와 서버 검증 위임은 별도 역할이다. 기존 단말의 외부 데이터 처리 기능, 오프라인·갱신 실패 정책, 목록 관리 권한과 Root 침해 시 복구는 미확인이다. 현재 FOTA 전용이라는 조건을 서버 도입만으로 해소했다고 보지 않는다.

**확인 질문**

> 단말은 서버에 접속하지 못하는 동안에도 인증서나 콘텐츠 서명을 검증해야 하나요? 이 조건에 따라 ‘First 목록을 받아 단말에서 검증’하는 방식과 ‘서버에 검증을 맡기는 방식’의 적합성이 달라집니다.

# 06. 검토 결과와 보완 내역

## 검토 범위와 방법

2026년 9월 17일, 세 서브에이전트가 키·프로파일, 운영·세레모니, Conformance 신청·적용 범위를 나누어 요구사항 분석을 검토했다. 조사 기준에 명시한 공식 정책·사양과 분석 내용을 대조하고, 지적 사항을 반영한 뒤 재검토했다. 이 검토는 분석 보고서의 정확성을 확인하기 위한 절차이며 C2PA의 공식 적합성 심사는 아니다.

## 1차 검토와 보완

초기 검토에서는 높음 1건, 보통 5건, 낮음 3건으로 총 9건이 확인되었다. 각 항목을 공식 원문과 대조하여 다음과 같이 보완했다.

| 검토 항목 | 중요도 | 보완 내용 | 관련 요구사항 |
|---|---|---|---|
| Root AKI의 정책·검사 차이 | 보통 | 정책·프로파일의 선택 조건과 schema의 필수 검사를 구분 | 제1장 AKI 비교표, Q11 |
| documentSigning OID 차이 | 높음 | Spec의 표준 OID와 certificate/CSR schema의 다른 OID를 구분하고 심사 수용 여부 확인 항목 추가 | 제1장 schema 차이, Q12 |
| 인력 배경조사·보안인가 | 보통 | 단순 신원확인으로 축약하지 않고 background checks와 clearance 절차 명시 | O05 |
| 개인키 노출 폐지 조건 | 낮음 | 개인키 노출이 확인된 경우라는 원문 조건 명시 | O21 |
| 운영 권고 범위 | 낮음 | 일반 backup의 off-site 보관, 교체 시 신뢰 연속성, 사고 대응 역할·연습, 종료 시 안전한 처분 추가. 소문자 should의 강도 유지 | O15, O17, O19, O20 |
| TSA 시각 정확도 | 보통 | 권고 정확도를 오차 1초 이하로 명확화 | T01 |
| maxAL 이하 발급 | 보통 | maxAL 이하 모든 수준 발급 SHALL과 요청별 하위 AL 평가 MAY를 함께 표시 | E11, Q10 |
| 신뢰 목록 제거 대응 | 보통 | 통지, Task Force 검토, Steering Committee 결정 및 분쟁 절차 추가 | E16 |
| 근거 참조 표시 | 낮음 | 발급 책임·프로파일 요구의 출처가 표에서 누락되지 않도록 보완 | E12, E13 |

## 2차 검토 결과

보완 후 세 검토 영역 모두에서 추가 지적이 없었다.

| 검토 영역 | 재검토 범위 | 결과 |
|---|---|---|
| 키·인증서 | 네 CA 프로파일, CA 인증서·CSR schema 주요 제약, 키 생성·보호·사용, Spec 관련 요건 | 앞선 지적 해소, 추가 지적 없음 |
| 관리·운영·세레모니 | 운영 통제, 키 생성 대본, cloud 적용 조건, 다인 통제, 백업·기록·폐지 | 앞선 지적 해소, 추가 지적 없음 |
| Conformance·적용 범위 | 신청·등록 증거, CA 책임, AL 발급, TSA 요구, 제품 의무와 CA 의무의 경계 | 앞선 지적 해소, 추가 지적 없음 |

총 2회 검토를 수행하고 1차 지적 9건을 모두 반영했다. 일반화 편집 과정에서 원문 요구사항, 적용 대상, 의무 수준과 출처를 유지했다.

## 원문 schema 차이의 확인 범위

Root AKI와 documentSigning의 차이는 JSON Schema Draft 2020-12 방식으로 해당 schema 조건을 검사한 8개 사례에서도 확인했다.

- Root AKI 조건: AKI를 생략하면 실패하고 포함하면 통과한다.
- Claim Issuing certificate 및 CSR의 EKU 조건: c2pa-kp-claimSigning과 표준 documentSigning OID의 조합은 실패한다. schema에 적힌 다른 OID 또는 emailProtection과의 조합은 통과한다.

이 결과는 **개별 schema 조건의 동작**을 확인한 것이다. 전체 인증서의 적합성, 공식 checker 결과 또는 운영 통제의 적합성을 입증하지 않는다. 직접적인 근거는 제1장과 Q11·Q12에 연결한 공식 schema와 Spec이다.

## 후속 확인 사항

Q01–Q12는 공식 자료의 차이와 심사 수용 범위에 관한 확인 사항이다. 관련 설계를 확정하기 전에 확인 결과를 반영해야 한다. 실제 키 생성·발급·운영 통제·계약·등록의 적합성은 별도의 구현 증거와 C2PA 심사로 확인한다.

# 확정된 설계 결정

현재 적용할 것으로 확정된 내용과 그 출처를 모은다. 선택지 비교는 [검토 기록](../reviews/README.md)에, 질문과 사용자 답변은 [문답 로그](../design-dialogue-log.md)에 남긴다. 설계 결정과 표준 적합성·구현 검증의 완료는 별도 상태다.

## 기존 확정 사항

아래는 [requirements.md의 사용자 확정 사항](../requirements.md#사용자-확정-사항)을 연결한 목록이다. 기존 ID와 원기록을 유지하며, 이번 정리는 새로운 승인이나 재확정을 뜻하지 않는다. 최초 결정일·이유·대화 원문이 원기록에 충분히 남아 있지 않은 경우 이를 추정해 채우지 않는다.

| 기존 ID | 확정 내용 요약 | 적용 범위·남은 결정 |
|---|---|---|
| R01 | 플랫폼 Root가 서비스·기기 플랫폼의 ICA 인증서를 발급하며 첫 적용 대상은 C2PA | 다른 용도의 확장은 별도 설계 |
| R02 | Global과 CN이 동일한 Root 키를 공유하며 CN에 별도 CloudHSM을 구축하지 않음 | Root 개인키의 CN 복제를 뜻하지 않음 |
| R03 | CA 발급은 저빈도이며 일상 발급에 Global Root–CN 실시간 호출 의존성을 두지 않음 | 비동기 반입·반출 및 상태·신뢰 목록 배포는 상세 설계 대상 |
| R04 | Root 개인키를 AWS CloudHSM에서 관리 | First ICA의 동일 보관 방식은 아직 제안 |
| R05 | Root → C2PA First ICA → 하위 Issuing ICA → leaf를 기본 계층으로 기록하고 First의 Trust List 등록을 목표로 함 | 부서별 CA 구조는 [RV-001](../reviews/001-first-ica-structure.md), 그 구조에서의 용도별 ICA 사용은 후속 [RV-002](../reviews/002-purpose-ica-usage.md)에서 검토. 계층 변경이 결정되면 원기록도 갱신 |
| R06 | C2PA CP를 공통 운영 정책의 주요 참고 자료로 사용하고 Root에는 필요한 통제를 선별 적용 | 공식 의무의 적용 해석과 자율 채택 통제를 구분 |
| R07 | Root·First ICA를 통한 ICA 발급에 최소 2인 통제 적용 | 구현 방식과 2-of-3 구성은 미확정 |
| R08 | TSA ICA를 발급받은 운영 조직이 TSA 구현·운영을 담당 | 중앙은 발급·인계 경계와 증빙을 정의 |
| R09 | CRL을 발행하지 않고 OCSP만 사용 | 응답자 구성·상태 배포·장애 정책은 상세 설계 대상 |
| R10 | 단말 Root 교체와 향후 양자내성 전환을 설계하며 현재 갱신 수단은 FOTA로 기록 | 실제 저장소·검증 코드·부팅 키의 갱신 가능성은 조사 대상 |
| R11 | 운영 책임자·승인 조직의 실제 지정은 보류 | 역할과 필요한 권한부터 정의 |

이 표는 기존 결정의 요약 색인이다. 기존 R 항목의 정확한 내용과 영향은 requirements.md에서 관리한다. D 항목의 제안이나 V 항목의 미확인 사항은 이관 과정에서 확정 결정으로 바꾸지 않는다.

## 문답에서 추가된 요구사항

- **R12 — 하위 부서 구분을 고려:** 2026-09-21 [Q02](../design-dialogue-log.md#q02)의 사용자 요청을 [requirements.md](../requirements.md)에 기록했다. 검토 범위를 추가한 것이며, 부서별 First 채택이나 부서에 키·발급 권한을 위임하는 결정은 아니다.

## 문답을 통해 추가한 설계 결정

아직 없다. First ICA 구조는 비교 중이며 어느 안도 확정하지 않았다.

먼저 RV-001의 부서별 구조·책임 결정을 기록하고, RV-002의 용도별 ICA 구성·운영 결정에서 해당 선행 결정 ID를 참조한다. 검토 순서의 정정은 어느 CA 구조나 용도별 구성을 채택했다는 뜻이 아니다.

새로 확정하는 설계 결정은 `DEC-번호`와 주제별 파일로 기록하고 이 절에서 연결한다. 기존 R 번호와 제안을 뜻하는 D 번호는 재사용하지 않는다.

## 결정 문서에 남길 내용

- **결정:** 채택한 방식과 적용 범위를 첫 문장에 명시한다.
- **결정일·출처:** KST 날짜와 방향을 확정한 사용자 답변 또는 기존 확정 기록을 연결한다.
- **선행 결정:** 이 결정이 전제로 삼는 부서별 구조·책임 등 앞선 결정 ID와 적용 조건을 연결한다.
- **이유·조건:** 선택 이유, 주요 제약, 결정이 성립하는 가정과 남은 검증을 적는다. 세부 대안 비교는 해당 RV 기록을 연결한다.
- **반영 위치:** requirements.md와 상세 설계의 변경 위치 및 반영 여부를 적는다.
- **변경 관계:** 상태를 `유효`, `대체됨`, `철회됨`으로 표시하고 이전·후속 결정을 연결한다.

변경 결정이 나면 이전 결정의 본문을 새 내용으로 덮어쓰지 않고 후속 결정으로 대체 관계를 기록한다. 확정되지 않은 대안은 reviews/에서 관리한다.

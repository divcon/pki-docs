# 설계 검토 기록

선택지가 갈리는 설계 문제의 검토 과정을 주제별로 기록한다. 질문, 선택지, 비교 전제, 판단 기준, 원문 근거, 남은 확인 사항을 남긴다. 검토 문서는 설계 방향의 확정이나 표준 적합성의 증명이 아니다.

## 검토 순서와 의존 관계

부서별 CA 구조와 운영 책임을 먼저 검토하고, 그 결과를 바탕으로 각 ICA의 용도와 사용 방식을 검토한다. 두 주제는 선행·후속 관계로 연결한다.

| 순서 | 검토 | 입력 | 다음 검토에 넘길 결과 | 상태 | 확정 결정 |
|---|---|---|---|---|---|
| 1 | [RV-001 — 부서별 CA 계층과 운영 책임](001-first-ica-structure.md) | 기존 요구사항, 하위 부서 구분, 단말 인증서의 FOTA 갱신 제약 | 부서별 또는 공용 First 구조, 중앙·부서 책임, 단말 신뢰·FOTA·계층 제약 | 검토 중 | 없음 |
| 2 | [RV-002 — ICA 용도와 사용 방식](002-purpose-ica-usage.md) | RV-001에서 나온 확정 결정과 적용 조건 | 해당 구조에서 Claim·TSA 등 ICA의 배치·발급·인계·운영 방식 | 선행 결정 대기 | 없음 |

RV-002의 외부 제약·사용 목적은 미리 조사할 수 있다. 최종 용도별 구성을 결정할 때는 선행 결정 ID를 연결한다. 후속 검토에서 구조상 충돌이 발견되면 RV-001을 재검토하고 변경 관계를 기록한다.

아직 문답을 시작하지 않은 기존 제안과 검증 과제는 [requirements.md의 D·V 항목](../requirements.md)에 있다. 해당 주제를 다룰 때 검토 기록을 만들고 연결한다.

## 관리 방식

1. 새 주제에 `RV-번호`를 부여하고 파일 하나에 결정할 질문과 선택지를 적는다. 선행·후속 검토와 입력·출력을 명시한다.
2. [문답 로그](../design-dialogue-log.md)의 관련 질문을 연결한다. 비교의 가정, 사용자 답변, 외부 원문에서 확인한 사실과 설계 판단을 구분한다.
3. 검토 과정은 날짜별로 추가한다. 설명을 수정하면 바뀐 이유를 남기고 이전 판단을 추적할 수 있게 한다.
4. 방향이 확정되면 [확정 결정](../decisions/README.md)을 별도 작성하고 연결한다. 검토 문서는 선택지와 판단 과정의 기록으로 보존한다.

상태는 `검토 중`, `선행 결정 대기`, `보류`, `결정 연결됨`으로 표시한다. `결정 연결됨`은 기술 검증 완료를 뜻하지 않는다. 재검토 시 현재 적용되는 결정과 바꾸려는 범위를 명시하며, 새 결정 전까지 기존 결정의 적용 여부를 임의로 바꾸지 않는다.

## 검토 문서에 남길 내용

- 결정할 질문과 관련 설계 항목·요구사항
- 선행·후속 검토, 필요한 입력과 다음 검토에 넘길 결과
- 선택지와 비교 전제
- 판단 기준, 장단점, 근거와 확인 결과
- 남은 질문과 결정에 필요한 정보
- 검토 이력, 관련 문답과 확정 결정 링크
